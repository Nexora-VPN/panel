# نصب Nexora

Nexora از یک پنل (لایهٔ کنترل) و هر تعداد نود (لایهٔ داده) تشکیل شده است. این
صفحه پنل را نصب می‌کند. نودها بعداً از داخل خود پنل اضافه می‌شوند و پنل برای هر
کدام یک دستور تک‌خطی به شما می‌دهد.

اسکریپت نصب هیچ سؤالی نمی‌پرسد. تنها تصمیمی که به‌جای شما می‌گیرد دیتابیس است —
و همان یک مورد است که پنل نمی‌تواند بعداً انتخابش کند، چون بدون دیتابیس اصلاً
تنظیماتی ندارد. باقی موارد — مدیر اصلی، پورت، مسیرهای محرمانه، HTTPS — در صفحهٔ
راه‌اندازی انتخاب می‌شوند که اولین بار که پنل را باز کنید نمایش داده می‌شود.

## پیش‌نیازها

- یک سرور لینوکس ۶۴ بیتی با systemd (دبیان ۱۱ به بالا، اوبونتو ۲۰.۰۴ به بالا،
  RHEL 9 به بالا یا مشابه). ARM و x86 سی‌ودو بیتی هم پشتیبانی می‌شوند.
- دسترسی root.
- یک پورت TCP باز برای پنل (به‌صورت پیش‌فرض ۲۰۹۵). پنل روی وایلدکارد IPv6 بایند
  می‌شود که IPv4 را هم پاسخ می‌دهد، پس سرور فقط‌IPv4، فقط‌IPv6 یا dual-stack همگی
  بدون تغییر کار می‌کنند.

## نصب

با SQLite، که به هیچ سرویس دیگری نیاز ندارد:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/nexora-vpn/panel/main/install.sh)
```

با PostgreSQL، که اسکریپت نصب خودش آن را نصب و پیکربندی می‌کند:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/nexora-vpn/panel/main/install.sh) --postgres
```

برای نصب نسخه‌ای مشخص، `--version v1.2.3` را اضافه کنید.

پنل و نود جدا از هم منتشر می‌شوند، بنابراین شماره نسخه‌شان هم جداست. اسکریپت نصب
در کنار پنل، باینری‌های نود را هم آماده می‌کند — همان چیزی که پنل بعداً به
نصب‌کننده‌های نود می‌دهد؛ `--node-version v1.2.3` آن‌ها را روی نسخه‌ای مشخص قفل
می‌کند. بدون آن آخرین نسخهٔ نود گرفته می‌شود، که همان چیزی است که می‌خواهید مگر
اینکه بخواهید یک ناوگان مشخص را بازسازی کنید.

پیش‌فرض درست SQLite است: دیتابیس یک پنل Nexora کوچک است و یک فایل، پشتیبان‌گیری و
جابه‌جایی را بسیار ساده‌تر می‌کند. وقتی از قبل PostgreSQL دارید یا پنل شما تعداد
کاربر بالایی را سرویس می‌دهد، سراغ PostgreSQL بروید.

## تکمیل راه‌اندازی

اسکریپت نصب در پایان لینکی مانند این چاپ می‌کند:

```
http://203.0.113.10:2095/setup?t=9f3c1ad2…
```

آن را باز کنید. این توکن اجازهٔ ساختن حساب مدیر اصلی را می‌دهد، پس مانند یک
گذرواژه با آن رفتار کنید و جای عمومی نگذاریدش. به‌محض کامل شدن راه‌اندازی از کار
می‌افتد.

تا وقتی راه‌اندازی تمام نشده، پنل به **هیچ چیز دیگری** پاسخ نمی‌دهد: هر مسیر
دیگری — صفحهٔ ورود، API، لینک‌های اشتراک — ۴۰۴ می‌گیرد، و خود صفحهٔ راه‌اندازی هم
بدون توکن ۴۰۴ می‌شود. پس پنلِ راه‌اندازی‌نشده روی یک IP عمومی چیزی برای اسکنر
باقی نمی‌گذارد.

اسکریپت نصب برای هر نشانی‌ای که پیدا کند یک لینک چاپ می‌کند، به‌علاوهٔ یک لینک
برای نشانی‌ای که اینترنت این هاست را با آن می‌بیند. هر کدام که واقعاً به سرور
می‌رسد را استفاده کنید: روی یک VPS معمولاً همان نشانی عمومی است، و روی هاست
داکر بیشتر بقیه آدرس‌دهی مجازیِ بریج است که به هیچ‌جا نمی‌رسد.

نشانی IPv6 در آن لینک‌ها داخل براکت می‌آید، که همان چیزی است که یک URL لازم دارد —
`http://[2001:db8::10]:2095/setup?t=…`. کاملش را کپی کنید؛ مرورگر بدون براکت
قبولش نمی‌کند.

اگر لینک‌ها را گم کردید، توکن را دوباره روی سرور چاپ کنید و نشانی را دور آن
بسازید:

```bash
nexora-panel setup-token
# ← 9f3c1ad2…   سپس http://YOUR-SERVER:2095/setup?t=9f3c1ad2… را باز کنید
```

ویزارد همه‌چیز را در یک فرم می‌گیرد و در یک مرحله ذخیره می‌کند:

- **مدیر اصلی** — حسابی که پنل را پیکربندی می‌کند و همهٔ اشتراک‌ها را می‌بیند.
  دست‌کم ۱۲ کاراکتر، شامل سه مورد از: حروف کوچک، حروف بزرگ، رقم، نماد.
- **نشانی پنل** — آی‌پی و پورتی که روی آن گوش می‌دهد، و مسیر محرمانه‌ای که پنل زیر
  آن پاسخ می‌دهد. یک مسیر تصادفی پیشنهاد می‌شود؛ نگه‌داشتن آن یعنی اسکنرهایی که
  پورت شما را پیدا می‌کنند، صفحهٔ ورود را پیدا نمی‌کنند.
- **مسیر اشتراک** — جایی که لینک‌های اشتراک روی آن ساخته می‌شوند. باید با مسیر پنل
  فرق کند.
- **HTTPS** — به‌صورت پیش‌فرض روشن. پنل گواهی خودش را صادر و پیش از انقضا تمدید
  می‌کند.
  - **نشانی‌های گواهی** از پیش با نشانی‌ای که ویزارد را با آن باز کرده‌اید و هر
    نشانی عمومیِ پیداشده روی ماشین پر می‌شود. آن‌ها را ویرایش کنید: پنل نمی‌تواند
    بداند کلاینت‌های شما از چه نشانی‌ای استفاده می‌کنند. داخل کانتینر فقط
    آدرس‌دهی بریج را می‌بیند و پشت NAT، نشانی عمومی اصلاً روی هیچ اینترفیسی
    نیست — پس اگر نشانی‌ای که در مرورگر تایپ می‌کنید در فهرست نیست، اضافه‌اش کنید.
    نشانی‌های IPv6 را به شکل ساده بنویسید (`2001:db8::10`)؛ براکت هم پذیرفته و
    حذف می‌شود.
  - با افزودن دامنه، گواهی برای پوشش آن دوباره صادر می‌شود و دامنهٔ اشتراک هم روی
    همان گواهی می‌نشیند.
  - می‌توانید HTTPS را خاموش کنید، اما آن‌وقت گذرواژه‌ها و لینک‌های اشتراک به‌صورت
    متن ساده منتقل می‌شوند.
- **منطقهٔ زمانی** — همهٔ زمان‌های نمایش‌داده‌شده در پنل بر اساس آن رندر می‌شوند.

با ذخیره، پنل روی نشانی‌ای که توصیف کردید دوباره راه‌اندازی می‌شود و مرورگر به
همان‌جا می‌رود. با گواهی خودامضا مرورگر یک بار هشدار می‌دهد؛ بپذیرید و ادامه دهید.

## داکر

دو استک، هر کدام برای یک دیتابیس. یکی را انتخاب و اجرا کنید:

```bash
git clone https://github.com/nexora-vpn/panel
cd panel/docker/sqlite      # یا: cd panel/docker/postgres
docker compose up -d
docker compose logs panel | grep setup
```

برای استک PostgreSQL، پیش از اولین اجرا فایل `.env.example` را به `.env` کپی و
یک گذرواژه در آن تنظیم کنید.

هر استک آنچه را باید از کانتینر جان سالم به در ببرد کنار فایل compose نگه می‌دارد:
دیتابیس SQLite در `./data` (استک PostgreSQL به‌جایش از یک volume نام‌دار استفاده
می‌کند)، باینری‌های نود در `./bin` و آرشیوهای پشتیبان در `./backups` — بخش
«پشتیبان‌گیری» را ببینید.

در داکر، پورت پنل با `NEXORA_WEB_LISTEN` در فایل compose قفل می‌شود، چون نگاشت
پورت منتشرشده هم همان‌جاست. تغییر پورت از داخل رابط پنل فقط کانتینر را
غیرقابل‌دسترس می‌کند، پس هر دو را با هم تغییر دهید.

`NEXORA_WEB_LISTEN` بایند *داخل* کانتینر است؛ آنچه به هاست می‌رسد نگاشت `ports:`
است و داکر جز در صورت تنظیم صریح فقط روی IPv4 منتشر می‌کند. روی هاست فقط‌IPv6،
IPv6 را در دیمن فعال کنید (`"ipv6": true` و `"ip6tables": true` در
`/etc/docker/daemon.json`) و روی هر دو منتشر کنید:

```yaml
    ports:
      - "0.0.0.0:2095:2095"
      - "[::]:2095:2095"
```

### پنل و نود روی یک سرور

پوشهٔ `docker/panel-and-node` همان استک SQLite است با یک نود در کنارش.
**پیشنهاد نمی‌شود**: آدرس نود در هر لینک اشتراکی که می‌دهید نوشته می‌شود، پس اجرای
نود در اینجا آدرس پنل را به همهٔ کاربران نشان می‌دهد؛ و ترافیک کاربر بی‌سقف است، پس
نودی که زیر بار برود پنل — و اشتراک کاربران همهٔ نودهای دیگر — را هم با خودش پایین
می‌کشد. برای آزمایشگاه، دمو، یا یک راه‌اندازی کوچک تک‌سروری معاملهٔ منطقی‌ای است.
[راهنمای نصب نود](https://github.com/nexora-vpn/node/blob/main/docs/fa/install.md#پنل-و-نود-روی-یک-سرور)
همهٔ هشدارها را کامل آورده است.

نود پیش از استارت به گواهی کلاینت پنل نیاز دارد و پنل آن را تنها وقتی می‌دهد که
نودی در آن اضافه شده باشد — پس این استک در دو گام بالا می‌آید:

```bash
cd panel/docker/panel-and-node
docker compose up -d panel
docker compose logs panel | grep setup      # لینک را باز و ویزارد را تمام کنید

# بعد در پنل: نودی با آدرس 127.0.0.1 و پورت 62050 اضافه کنید و گواهی کلاینت را
# از صفحهٔ نصب همان نود در مسیر ./certs/panel_ca.pem ذخیره کنید
docker compose up -d node
```

هر دو سرویس از شبکهٔ host استفاده می‌کنند — نود به این خاطر که پورت‌های inboundهایش
بعداً در پنل انتخاب می‌شوند، و پنل به این خاطر که بتواند نود را روی ۱۲۷.۰.۰.۱
ببیند. در نتیجه هیچ نگاشت پورتی نمی‌ماند که لازم باشد هماهنگ نگه داشته شود، و این
تنها استکی است که `NEXORA_WEB_LISTEN` را قفل *نمی‌کند*: پورتی که در ویزارد انتخاب
می‌کنید مستقیم روی خود هاست بایند می‌شود، مثل نصب معمولی. پورت کنترلی نود هم اصلاً
از ماشین بیرون نمی‌رود و قانون فایروال نمی‌خواهد.

## به‌روزرسانی

اسکریپت نصب را دوباره اجرا کنید. نصب موجود را تشخیص می‌دهد و در همان جا
به‌روزرسانی می‌کند:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/nexora-vpn/panel/main/install.sh)
```

سرویس را متوقف می‌کند، از دیتابیس SQLite در `nexora.db.bak` پشتیبان می‌گیرد،
باینری قبلی را در `/opt/nexora-panel/nexora-panel.previous` نگه می‌دارد، مهاجرت را
اجرا می‌کند و دوباره سرویس را بالا می‌آورد. `config.json`، تنظیمات و حساب‌های
مدیران دست‌نخورده می‌مانند. اگر از PostgreSQL استفاده می‌کنید، پیش از آن خودتان
یک dump بگیرید.

در داکر به روال معمول:

```bash
docker compose pull && docker compose up -d
```

## دسترسی‌تان قطع شد؟

هر تنظیمی که می‌تواند پنل را غیرقابل‌دسترس کند، بدون اجرای پنل از خط فرمان قابل
نوشتن است:

```bash
nexora-panel config list                       # چه چیزی تنظیم شده
nexora-panel config set web_listen_port 2095   # پورتی که به آن دسترسی دارید
nexora-panel config set web_listen_ip ""       # بایند دوباره روی همه‌جا (v4 و v6)
nexora-panel config set web_domain ""          # برداشتن محدودیت نام میزبان
nexora-panel config set web_basepath ""        # بازگشت به سرو روی ریشه
systemctl restart nexora-panel
```

اسکریپت نصب، `nexora-panel` را روی PATH قرار می‌دهد و خود باینری فایل پیکربندی‌اش
را پیدا می‌کند، پس این دستورها از هر پوشه‌ای کار می‌کنند. در داکر، پیشوند
`docker compose exec panel /app/` را بگذارید.

## IPv6

هیچ‌چیز اینجا نیاز به تنظیم ندارد. پنل به‌صورت پیش‌فرض روی `[::]:2095` گوش می‌دهد که
روی هاست dual-stack به IPv4 هم پاسخ می‌دهد؛ هاستی که IPv6 در آن خاموش است نمی‌تواند
این را بایند کند و پنل خودش به `0.0.0.0:2095` برمی‌گردد. برای بایند شدن روی فقط یک
خانواده، `web_listen_ip` را در ویزارد یا از خط فرمان روی یک نشانی مشخص (`::` یا
`0.0.0.0`، یا یک نشانی خاص) بگذارید.

نودها از آن طرف همین داستان را دارند: نودی که فقط نشانی IPv6 دارد با نشانی‌اش به
شکل ساده اضافه می‌شود (`2001:db8::1`، براکت اختیاری) و پنل هرجا که نحو لازم دارد
براکت می‌گذارد — لینک‌های اشتراک‌گذاری به شکل `vless://…@[2001:db8::1]:443?…`
درمی‌آیند و پروفایل وایرگارد به شکل `Endpoint = [2001:db8::1]:51820`، در حالی که
پروفایل clash، sing-box یا OpenVPN نشانی را بدون براکت می‌گیرد. URLهای اشتراک که
روی نشانی IPv6 پنل ساخته می‌شوند هم به همین دلیل براکت می‌گیرند.

## پشتیبان‌گیری

پنل از دیتابیس خودش پشتیبان می‌گیرد؛ از **تنظیمات ← پشتیبان** در نوار کناری (فقط
مدیر اصلی — یک آرشیو همهٔ اعتبارنامه‌هایی را که پنل دارد در خود نگه می‌دارد).

آرشیو یک دامپ منطقی از تمام جدول‌ها داخل یک tar فشرده است، نه کپی فایل دیتابیس. به
همین دلیل آرشیوی که روی SQLite گرفته شده روی PostgreSQL بازگردانده می‌شود و
برعکس، و به همین دلیل راه انتقال پنل به سرور دیگر همین است.

```
تنظیمات ← پشتیبان
├─ دانلود              مستقیم در مرورگر شما؛ چیزی روی سرور نمی‌ماند
├─ گرفتن روی سرور      داخل پوشهٔ پشتیبان نوشته می‌شود
├─ زمان‌بندی           پیش‌فرض خاموش: فاصله به ساعت، و تعداد نگهداری
└─ بررسی / بازگردانی   اول آرشیو را وارسی کنید، بعد دیتابیس را با آن جایگزین کنید
```

**کجا نگه داشته می‌شوند.** در نصب معمولی `/var/opt/nexora/backups`. در داکر،
استک‌ها پوشهٔ `./backups` کنار همان `docker-compose.yml` را mount می‌کنند تا
آرشیوها روی هاست بمانند و با کانتینر از بین نروند. در هر دو حالت، یک نسخه از آن
پوشه را جای دیگری ببرید — پشتیبانی که فقط روی همان ماشینِ محافظت‌شونده وجود دارد،
پشتیبان نیست.

**رمزگذاری.** گذرواژه اختیاری است و روی دانلود، پشتیبان‌های گرفته‌شده روی سرور و
پشتیبان‌های زمان‌بندی‌شده اعمال می‌شود (scrypt + AES-GCM). پنل آن را فقط برای
رمزگذاری نگه می‌دارد؛ گذرواژهٔ گم‌شده را نمی‌تواند بازیابی کند و آرشیوی که باز
نشود بازگردانی هم نمی‌شود — پس گذرواژه را کنار مقصدی نگه دارید که آرشیوها را
آنجا می‌برید، نه روی خود پنل.

**بررسی پیش از بازگردانی.** دکمهٔ *بررسی* آرشیو را بدون دست‌زدن به چیزی می‌خواند:
چه چیزی در آن هست، چه زمانی و با کدام نسخهٔ پنل گرفته شده، و چه هشدارهایی دارد —
آرشیوی از هاست دیگر (لایسنسش اینجا معتبر نیست)، آرشیوی بدون مدیر اصلی، یا آرشیوی
که بدون تاریخچهٔ ترافیک یا بدون گزارش رخدادها گرفته شده.

**بازگردانی.** بازگردانی همهٔ ردیف‌های دیتابیس را جایگزین می‌کند و پنل را دوباره
راه می‌اندازد. پیش از آن، یک **اسنپ‌شات پیش‌از‌بازگردانی** از دیتابیس فعلی در
همان پوشه می‌نویسد؛ سیاست نگهداری هرگز آن‌ها را پاک نمی‌کند، پس بازگردانیِ اشتباه
با بازگرداندن همان اسنپ‌شات جبران می‌شود. به‌صورت پیش‌فرض، بازگردانی تنظیمات نشانی
*همین* نصب (پورت، دامنه، مسیر، TLS) و لایسنس آن را نگه می‌دارد تا آرشیوی از ماشین
دیگر، پنل را به نشانی‌ای که این سرور ندارد نبرد.

**انتقال به سرور دیگر.** پنل را روی سرور جدید نصب کنید، لینک راه‌اندازی را باز
کنید و در نخستین صفحهٔ ویزارد به‌جای پر کردن فرم، گزینهٔ *از سرور دیگری می‌آیید؟
از پشتیبان بازیابی کنید* را دنبال کنید. این تنها جایی است که بازگردانی پیش از وجود
حساب کار می‌کند — و دقیقاً وضعیت یک نصب تازه همین است — و اینجا تنظیمات خودِ آرشیو
گرفته می‌شود، چون نصب خالی چیزی برای نگه‌داشتن ندارد. لایسنس منتقل نمی‌شود: به
اثر انگشت سخت‌افزاری هاست گره خورده، پس کلید خود را روی سرور جدید نصب کنید
(`nexora-panel hwid` همان اثر انگشت را چاپ می‌کند).

**از خط فرمان**، برای نصب بدون رابط گرافیکی یا نصب اسکریپتی:

```bash
nexora-panel config set backup_enabled true
nexora-panel config set backup_interval_hours 24    # روزانه
nexora-panel config set backup_keep 14              # ۰ یعنی هیچ‌چیز پاک نشود
nexora-panel config set backup_dir /var/opt/nexora/backups   # باید مطلق باشد
nexora-panel config set backup_passphrase "یک گذرواژهٔ بلند"
```

زمان‌بندی در تیک ساعتی بعدیِ پنل خوانده می‌شود، پس هیچ‌کدام از این‌ها نیاز به
راه‌اندازی مجدد ندارند. `backup_passphrase` هرگز توسط `config list` یا `config
get` چاپ نمی‌شود. در داکر، این دستورها را با `docker compose exec panel /app/`
اجرا کنید.

## حذف نصب

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/nexora-vpn/panel/main/install.sh) --uninstall
```

سرویس و `/opt/nexora-panel` حذف می‌شوند. دیتابیس *و پشتیبان‌های* شما در
`/var/opt/nexora` عمداً باقی می‌مانند؛ هر وقت مطمئن شدید دیگر لازمشان ندارید،
خودتان پاکشان کنید — و اگر خودِ سرور قرار است برود، اول یک نسخه از
`/var/opt/nexora/backups` را جای دیگری ببرید.

## هر چیزی کجاست

| مسیر | چیست |
| --- | --- |
| `/opt/nexora-panel/nexora-panel` | باینری |
| `/opt/nexora-panel/config.json` | فقط اتصال دیتابیس |
| `/var/opt/nexora/nexora.db` | دیتابیس SQLite |
| `/var/opt/nexora/bin/` | باینری‌های نود که پنل به نصب‌کنندهٔ نود می‌دهد |
| `/var/opt/nexora/sub-themes/` | قالب‌های صفحهٔ اشتراک |
| `/var/opt/nexora/backups/` | آرشیوهای پشتیبان و اسنپ‌شات‌های پیش‌از‌بازگردانی (دسترسی 0700) |
| `/etc/systemd/system/nexora-panel.service` | یونیت سرویس |

باقی موارد — مدیران، تنظیمات، گواهی‌ها، نودها، کاربران — در دیتابیس زندگی می‌کنند
و از داخل پنل مدیریت می‌شوند.
