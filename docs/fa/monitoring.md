# پایش

پنل اعداد خودش را روی `/metrics` با قالب Prometheus منتشر می‌کند، و این مخزن یک
تنظیم scrape، یک داشبورد Grafana و یک overlay داکرکامپوز می‌آورد که هر دو سرویس
را کنار پنل شما بالا می‌آورد.

## شروع سریع با داکر

این یک **overlay** است: دو سرویس به همان فایل کامپوزی که الان اجرا می‌کنید اضافه
می‌کند، پس به شبکهٔ پنل می‌پیوندند و با نام سرویس به آن می‌رسند. پنل هیچ پورت
اضافه‌ای منتشر نمی‌کند.

```bash
# ۱. پوشهٔ monitoring را کنار docker-compose.yml خودتان بگذارید
curl -fsSL https://github.com/nexora-vpn/panel/archive/refs/heads/main.tar.gz \
  | tar -xz --strip-components=1 panel-main/monitoring

# ۲. یک توکن در پنل بسازید (پایین) و در فایلی که Prometheus می‌خواند بگذارید
printf '%s' 'TOKEN-RA-INJA-BEGZARID' > monitoring/prometheus/token

# ۳. رمز Grafana را تعیین کنید
cp monitoring/.env.example .env      # یا این خطوط را به .env موجودتان اضافه کنید
${EDITOR:-nano} .env

# ۴. بالا بیاورید
docker compose -f docker-compose.yml -f monitoring/docker-compose.monitoring.yml up -d
```

**از این به بعد همیشه هر دو `-f` را بدهید.** کامپوز فایل‌هایی که به آن می‌دهید را
کل توصیف پروژه می‌داند، پس یک `docker compose up -d` سادهٔ بعدی این دو سرویس را
دوباره پاک می‌کند. اگر یادتان می‌رود، یک‌بار تنظیمش کنید:

```bash
echo 'COMPOSE_FILE=docker-compose.yml:monitoring/docker-compose.monitoring.yml' >> .env
```

بعد به Grafana برسید. فقط روی loopback منتشر شده، چون یک ورود دیگر است و آن ورودی
نیست که دارید می‌فروشید:

```bash
ssh -L 3000:localhost:3000 you@your-server
# بعد http://localhost:3000 را باز کنید و با GRAFANA_PASSWORD وارد شوید
```

داشبورد **Nexora fleet** از قبل آنجاست، در پوشه‌ای به نام Nexora، با datasource
وصل‌شده. چیزی برای import کردن نیست.

Prometheus عمداً **اصلاً** منتشر نمی‌شود. خودش هیچ احراز هویتی ندارد و کل تصویر
عملیاتی شما را نگه می‌دارد؛ منتشر کردنش همان دلیلی را که `/metrics` توکن می‌خواهد
باطل می‌کند. Grafana داخل شبکهٔ کامپوز به آن می‌رسد.

### اگر پنل شما خودش TLS می‌دهد

این hop هرگز از شبکهٔ داکر بیرون نمی‌رود، ولی اگر پنل خودش HTTPS سرو می‌کند
(تنظیمات ← وب، حالت `self_signed` یا `files`) باید Prometheus هم با آن HTTPS حرف
بزند. در `monitoring/prometheus/prometheus.yml`:

```yaml
    scheme: https
    tls_config:
      insecure_skip_verify: true
```

نادیده‌گرفتن تأیید گواهی اینجا **درست** است و میان‌بر نیست: گواهی پنل برای همان
نامی صادر شده که مشتریانتان استفاده می‌کنند، نه برای نام سرویس `panel` که
Prometheus صدا می‌زند — پس بررسی سخت‌گیرانه گواهی‌ای را رد می‌کرد که کاملاً درست
است.

### اگر پنل شما روی یک base path است

`/metrics` هم با آن جابه‌جا شده. بنویسید
`metrics_path: /your-base-path/metrics`.

## توکن

`/metrics` مثل هر مسیر دیگری احراز هویت می‌خواهد، و حالت بدون احراز هویت ندارد.
این سند نام هر نودی که دارید و آدرس هرکدام را می‌برد — مسیری که این را بی‌اجازه
بدهد، بعد از اینکه نصب‌ها از آن استفاده کردند دیگر قابل پس‌گرفتن نیست.

در پنل: **ادمین‌ها ← توکن‌های API ← افزودن**، با scope **`stats:read`** و هیچ‌چیز
دیگر. آن scope فقط به سطح مشاهده می‌رسد و به هیچ داده‌ای که نگرانش باشید نه.

توکن را در `monitoring/prometheus/token` بگذارید — فایلی جدا، نه مقداری داخل
`prometheus.yml` — چون فایل تنظیمات را آدم‌ها در issue و چت می‌چسبانند و یک
اعتبارنامه نباید با آن سفر کند. `.gitignore` مخزن از قبل حذفش کرده.

باطل‌کردن توکن در پنل، scrape را بلافاصله قطع می‌کند؛ چیزی کش نمی‌شود.

## بدون داکر

هر Prometheus‌ای می‌تواند scrape کند. حداقلش:

```yaml
scrape_configs:
  - job_name: nexora-panel
    scheme: https
    metrics_path: /metrics
    authorization:
      type: Bearer
      credentials_file: /etc/prometheus/nexora-token
    static_configs:
      - targets: ['panel.example.com']
```

بازهٔ ۶۰ ثانیه کافی است: اعداد میزبان که پشت سری‌های دیسک و حافظه‌اند هر پنج
دقیقه نمونه‌برداری می‌شوند، و شمارنده‌های ترافیک تجمعی‌اند، پس بین دو scrape چیزی
از دست نمی‌رود.

برای Grafana فایل `monitoring/grafana/dashboards/nexora-fleet.json` را import
کنید. به datasource‌ای با uid برابر `nexora-prometheus` ارجاع می‌دهد؛ یا همان uid
را به datasource خودتان بدهید، یا یک‌بار در JSON جایگزین کنید.

## چه چیزی صادر می‌شود

هر چیزی که پایین می‌آید یا به‌ازای نود است، یا به‌ازای یک دستهٔ ثابت، یا کل ناوگان.

**پنل**

| متریک | معنی |
| --- | --- |
| `nexora_panel_build_info` | عدد ۱، با نسخهٔ در حال اجرا به‌عنوان برچسب |
| `nexora_panel_start_time_seconds` | لحظه‌ای که پروسهٔ فعلی پنل listener را bind کرد؛ `time() - this` آپتایم آن است |

**لایسنس**

| متریک | معنی |
| --- | --- |
| `nexora_license_valid` | ۱ وقتی لایسنس درست است، ۰ روی سطح رایگان یا هر حالت نامعتبر |
| `nexora_license_expires_at_seconds` | تاریخ انقضا. وقتی لایسنس منقضی نمی‌شود، اصلاً نیست |
| `nexora_license_limit{resource}` | سقف هر منبع؛ صفر یعنی نامحدود |
| `nexora_license_used{resource}` | ردیف‌هایی که در برابر آن سقف شمرده می‌شوند |

**حساب‌ها**

| متریک | معنی |
| --- | --- |
| `nexora_users_total{status}` | حساب‌ها به تفکیک وضعیت: active، disabled، expired، limited، pending |
| `nexora_users_online` | حساب‌هایی که داخل پنجرهٔ آنلاین ترافیک داشته‌اند |

**نودها** — همهٔ این‌ها برچسب `node` (نام) و `id` دارند.

| متریک | معنی |
| --- | --- |
| `nexora_nodes_total` | پنل چند نود می‌شناسد |
| `nexora_node_up` | ۱ وقتی آخرین heartbeat وصل شد |
| `nexora_node_enabled` | ۱ وقتی خودتان نود را روشن گذاشته‌اید |
| `nexora_node_traffic_bytes_total{direction}` | ترافیکی که از زمان افزوده‌شدن نود به حسابش نوشته شده |
| `nexora_node_online_users` | حساب‌های متمایزی که روی آن نود در پنجرهٔ آنلاین ترافیک داشته‌اند |
| `nexora_node_connections` | اتصال‌هایی که موتور نود باز نگه داشته |
| `nexora_node_engine_restarts_total` | ری‌استارت‌های موتور از زمان شروع ایجنت نود |
| `nexora_node_disk_bytes`، `nexora_node_disk_used_bytes` | فایل‌سیستم ریشه |
| `nexora_node_memory_bytes`، `nexora_node_memory_used_bytes` | حافظهٔ میزبان |
| `nexora_node_load1` | میانگین بار یک‌دقیقه‌ای |

**گذرگاه رویداد** — تنها خرابی پنل که در غیر این صورت بی‌صداست، چون تحویلی که
هرگز نمی‌رسد، ذاتاً به هیچ‌کس گزارش نمی‌دهد.

| متریک | معنی |
| --- | --- |
| `nexora_event_deliveries{status}` | تحویل‌ها به تفکیک وضعیت: pending، delivered، dead |
| `nexora_event_subscribers` | چند مشترک فعال است |

## دو قاعده‌ای که باید بدانید

**عددی که نود گزارش نکرده، اصلاً سری ندارد.** دیسک، حافظه، بار، اتصال‌ها،
ری‌استارت موتور و شمار آنلاین هر نود همه مشروط‌اند: نودی با ایجنت قدیمی‌تر، یا
پلتفرمی بدون `/proc`، هیچ‌کدام را نمی‌گوید و پنل به‌جای صفر، **هیچ** صادر می‌کند.
صفر نموداری می‌کشید که در آن دیسک خودش خالی شده و همه آفلاین شده‌اند. پس
**شکاف در این نمودارها یعنی پنل نمی‌داند**، نه اینکه عدد افتاده — همان‌طور که
نوار آپتایم خود پنل هم همین را می‌کشد.

تنها استثنا `nexora_event_deliveries` است که همیشه هر وضعیت را گزارش می‌کند.
هشداری روی تحویل‌های مرده باید بتواند روی پنل سالم هم ارزیابی شود، وگرنه روی پنل
ناسالم هرگز شلیک نمی‌کند.

**هیچ‌چیز برچسب per-user ندارد.** یک برچسب به‌ازای هر کاربر یعنی یک سری زمانی
به‌ازای هر کاربر، تا هر وقت که retention شما باشد — ده هزار مشتری یعنی ده هزار
سری که هرگز بازنشسته نمی‌شوند، و این راه معمولِ تبدیل‌شدن یک استک پایش به همان
چیزی است که از کار می‌افتد. سؤال‌های سطح حساب را صفحهٔ **گزارش‌ها**ی خود پنل
درجا جواب می‌دهد، که می‌شود از آن دربارهٔ یک بازه پرسید به‌جای اینکه برای همیشه
scrape شود.

## هشدارهایی که ارزش دارند

چهارتا که به سروصدایشان می‌ارزند. آستانه‌ها را با ناوگان خودتان تنظیم کنید.

```yaml
groups:
  - name: nexora
    rules:
      # پنل جواب نمی‌دهد. بقیه‌چیزها پایین‌دست همین‌اند، پس پنجره را کوتاه‌تر از
      # یک ری‌استارت و بلندتر از آن نگه دارید که روی ری‌استارت شلیک نکند.
      - alert: NexoraPanelDown
        expr: up{job="nexora-panel"} == 0
        for: 5m

      # نودی که پنل باور دارد باید سرویس بدهد، جواب نمی‌دهد. نیمهٔ `enabled`
      # مهم است: نودی که خودتان خاموشش کرده‌اید قطعی نیست.
      - alert: NexoraNodeDown
        expr: nexora_node_up == 0 and nexora_node_enabled == 1
        for: 10m

      # دیسکی که پر شود نود را بی‌خبر می‌خواباند. پنل خودش هم روی ۹۰٪ رویداد
      # node.disk_high را بلند می‌کند؛ این نسخه‌ای است که حتی بدون نصب هیچ
      # افزونهٔ اعلانی به شما می‌رسد.
      - alert: NexoraNodeDiskFilling
        expr: nexora_node_disk_used_bytes / nexora_node_disk_bytes > 0.9
        for: 30m

      # تحویل‌هایی که تسلیم شده‌اند. هیچ‌چیز دیگری این را گزارش نمی‌کند: وبهوکی
      # که هرگز نمی‌رسد، ذاتاً به گیرنده‌اش چیزی نمی‌گوید.
      - alert: NexoraEventDeliveriesDead
        expr: increase(nexora_event_deliveries{status="dead"}[1h]) > 0
```

اگر روی لایسنس می‌فروشید، یک هشدار برایش هم می‌ارزد:
`nexora_license_valid == 0`، یا
`nexora_license_expires_at_seconds - time() < 7 * 86400`. بعد از تاریخ انقضا
هیچ مهلتی وجود ندارد، پس همان اطلاع کل جبرانش است.
