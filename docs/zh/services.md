# 面板服务

侧边栏的 **服务** 菜单（仅主管理员）放着面板与外界打交道的部分：Telegram 和邮件通知、
把每份备份另存一份到别处，以及用您在 Google、Microsoft、GitHub 或自己的身份服务器上
已有的账户登录。Webhook 也在这里。

| | |
| --- | --- |
| [不开启就是关闭的](#不开启就是关闭的) | 所有服务的共同点 |
| [Telegram](#telegram) | 聊天中的通知，以及几条只读命令 |
| [邮件](#邮件) | 同样的通知，以邮件发送 |
| [备份目的地](#备份目的地) | S3 兼容存储、SFTP、Telegram 聊天 |
| [单点登录](#单点登录) | 每个提供方一个登录按钮 |
| [扩展](#扩展) | 面板注册的独立程序 |

## 不开启就是关闭的

每个服务默认关闭，关闭的服务不运行任何东西，也不打开任何连接。每个服务都是一张结构
相同的卡片：

- **服务已开启**——开关。
- **它的设置。** 密码、令牌或密钥保存后不再显示：输入框里写着 *已设置——留空则保持不变*。
  留空就保留已保存的值。
- **测试**——测试的是 *已保存* 的设置，所以请先保存。
- **上次运行**——服务上次做事的时间，失败时还有最后一次错误。

服务的设置和面板的其他凭据一样存放在数据库中，因此会出现在每一份备份里——这也是
给备份设置密码的又一个理由。

## Telegram

**服务 → Telegram。** 面板把通知——客户即将到期或流量将尽、节点离线、备份失败——发到
Telegram 聊天，每个聊天配对到一个面板账户，只接收该账户有权看到的内容：
**代理商的聊天只会收到它自己客户的消息。**

**1. 创建 Bot。** 在 Telegram 中找 **@BotFather**，发送 `/newbot`，把它给出的令牌填进
**Bot 令牌**。请为面板单独创建一个 Bot：配对聊天时面板会读取 Bot 收到的消息，另一个
读取同一 Bot 的程序会先把消息取走。

**2. 如果面板在伊朗运行，** 从那里无法访问 `api.telegram.org`。填写以下其一：

- **代理**——`socks5://host:port` 或 `http://host:port`（用户名和密码写在地址里：
  `socks5://user:pass@host:port`）。
- **Bot API 地址**——您在境外运行的 [Bot API 服务器](https://github.com/tdlib/telegram-bot-api)，
  代替代理。

开启服务、保存，然后点 **测试**。

**3. 配对聊天。** 点 *配对聊天*，选择账户、通知语言以及要接收的事件，然后点 *获取代码*。
对话框会显示：

- 一个链接和二维码——在应接收通知的手机上打开并点 **Start**；
- 代码本身，可以手动发给 Bot；
- 对于 **群组**：*将 Bot 添加到群组*，选择群组后代码会自动发到那里；或者在 Bot 已加入的
  群组中发送 `/start@yourbot CODE` 这一行。在群组里 Bot 只能听到点名发给它的命令，
  所以单独发一个代码它看不到。

代码十分钟内有效。每个账户也可以从自己的菜单（**我的 Telegram**）配对自己的聊天——
代理商不需要主管理员帮忙。

**事件。** *该账户有权查看的全部事件* 也包括以后版本新增的事件。取消勾选即可自行选择；
账户无权查看的事件显示为灰色，永远不会发到它的聊天。无法送达的聊天会像 Webhook 一样
重试，所以在 Telegram 或代理中断期间发出的通知会在恢复后送达。

聊天所在行的 **投递记录** 列出发给它的每一条通知——已送达、等待重试或已放弃——以及
Telegram 的回应，每一条都可以 *重新发送*。每个账户都能在 **我的 Telegram** 中看到自己
聊天的投递记录。

**命令。** 在已配对的聊天中：

| 命令 | 回答 |
| --- | --- |
| `/status` | 摘要：按状态统计的账户与在线人数（代理商只看自己的），主管理员和操作员还能看到节点 |
| `/user name` | 一个账户：流量、到期、是否在线（代理商只看自己的） |
| `/node name` | 一个节点（主管理员和操作员） |

在群组中要加上 Bot 的名字：`/user@yourbot name`。命令只读；在聊天里无法更改面板中的任何东西。

## 邮件

**服务 → 邮件。** 同样的通知，以邮件发送。

| 设置 | |
| --- | --- |
| SMTP 服务器 | 邮件服务器名称，如 `smtp.gmail.com`——不带协议和端口 |
| 端口 | 留空 = STARTTLS 用 587，TLS 用 465，不加密用 25 |
| 安全 | **STARTTLS** 把普通连接升级为加密（通常 587）；**TLS** 从第一个字节起就加密（通常 465）；**无** 以明文发送一切，包括登录信息——仅用于本机或私有网络上的中继 |
| 证书 | **不验证** 仅用于您自己使用自签名证书的服务器 |
| 用户名、密码 | 用户名留空 = 不登录 |
| 发件人 | `Nexora <panel@example.com>`；大多数服务器只允许从您拥有的地址发信 |

**Gmail** 和大多数大型邮件服务不接受账户的普通密码登录 SMTP
（`534 Application-specific password required`）：为该账户开启两步验证，并改用
**应用专用密码**。

**添加地址。** *添加地址* 会向该地址发送一个六位数代码；把代码填回去即可添加。未经确认
的地址永远不会收到任何内容——打错一个字母也不会把您客户的名字发给陌生人。代码十分钟、
五次尝试内有效。每个账户都可以从自己的菜单（**我的邮件**）添加自己的地址，代理商的地址
只会收到它自己客户的消息。地址所在行的 **投递记录** 和聊天一样，显示发往该地址的内容。

## 备份目的地

**服务 → 备份目的地。** 面板写出的每一份备份——无论是计划任务还是在 **设置 → 备份**
中手动创建——都会在后台再发送到每个已开启的目的地。

**上传失败绝不会让备份失败。** 归档留在本服务器上，目的地显示错误，发出
`panel.backup_upload_failed` 事件（如果 Telegram 和邮件订阅了它，也会通知到），下一份
归档会再次发送。

**请先设置备份密码**（设置 → 备份）。归档包含面板的全部凭据；不加密的话，任何能读取
目的地的人都能拿到它们。没有密码时页面会给出警告。

### S3 兼容存储

Cloudflare R2、AWS S3、Backblaze B2、MinIO、伊朗的对象存储——任何支持 S3 协议的存储。

| 设置 | |
| --- | --- |
| 端点 | 存储地址，不含存储桶：`https://<account>.r2.cloudflarestorage.com`、`https://s3.<region>.amazonaws.com`、`https://s3.<region>.backblazeb2.com`，或您的 MinIO |
| 区域 | 留空 = `us-east-1`，R2 和 MinIO 都接受；AWS 需要存储桶所在的区域 |
| 存储桶 | 必须已经存在 |
| 访问密钥、秘密密钥 | 在该存储桶中有写入、列举和删除权限的密钥 |
| 文件夹 | 存储桶内的文件夹；留空 = 根目录 |
| 保留 | 在那里保留多少份归档；留空 = 备份页面的保留数，`0` = 全部保留 |

### SFTP

任何能通过 SSH 访问的服务器。

| 设置 | |
| --- | --- |
| 主机、端口 | 不带协议；端口留空 = 22 |
| 用户名 | |
| 密码、私钥 | 二者之一或都填；私钥为 PEM 或 OpenSSH 格式，不能带口令 |
| 主机密钥 | 首次连接时自动填写，之后每次连接都会校验——只有在那台服务器重装后才清空 |
| 目录 | 不存在时自动创建；留空 = 该用户的主目录 |
| 保留 | 同 S3 |

归档先以临时名称写入，完整上传后再改名，所以只传了一半的文件永远不会被当成备份。

### Telegram

把归档作为文件发到一个聊天，使用 Telegram 服务中保存的 Bot 及其代理。**聊天 ID** 是配对
到主管理员账户的聊天——即 Telegram 页面在它下面显示的数字。Bot API 只接受最大 **50 MB**
的文件；更大的归档会附带这个原因被拒绝，而不是发出去再失败。聊天中的内容永远不会被删除。

**保留规则。** 目的地中只会删除名称与面板归档相符的文件，所以同一个存储桶或目录里可以放
其他东西。

## 单点登录

**服务 → 单点登录。** 您添加的每个提供方，都会在登录页上出现一个 **使用 … 登录** 按钮。
无论哪个提供方，都遵循两条规则：

- **不会因此创建账户。** 每个账户自己关联身份：先用密码登录，在自己的菜单中打开
  **单点登录**，点 *通过 … 关联*。在提供方有账户、但在这里没有关联的人会被拒绝。
- **两步验证依然有效。** 启用了验证码的账户在提供方之后仍会被要求输入验证码，与密码登录
  之后一样。

**回调地址（Redirect URI）。** 页面会显示一个需要在每个提供方处登记的地址，以
`/api/login/oidc/callback` 结尾。它就是当前页面所在的地址，所以复制之前，请用操作员实际
使用的地址打开面板。

**添加提供方。** 点 *添加提供方*，在顶部选择提供方，表单只会询问该提供方需要的内容，
并在字段上方写明在该提供方的哪里创建客户端：

| 提供方 | 需要填写 |
| --- | --- |
| Google | Client ID、Client secret |
| Microsoft | Tenant（留空 = `common`，任何 Microsoft 账户）、Client ID、Client secret |
| GitHub | Client ID、Client secret |
| GitLab | 地址（留空 = gitlab.com）、Client ID、Client secret |
| Keycloak | 地址、Realm、Client ID、Client secret |
| Authentik | 地址、应用 slug、Client ID、Client secret |
| Okta | 域名、Authorization server（留空 = `default`）、Client ID、Client secret |
| Auth0 | 域名、Client ID、Client secret |
| OpenID Connect（其他） | Issuer、Client ID、Client secret、Scopes——PocketID、Authelia、Zitadel、Kanidm、Dex 等 |
| OAuth 2.0（其他） | authorization、token 和 user 三个地址，Client ID、Client secret，以及用户信息中哪些字段是 id 和名称 |

*测试* 检查提供方是否响应。*按钮名称* 修改按钮上的文字；*显示在登录页* 可以把按钮撤下而
不删除提供方。删除提供方会同时删除通过它关联的身份。

**被挡在门外？** `nexora-panel admin reset-password` 也会删除该账户的单点登录关联并关闭
它的两步验证，所以恢复命令始终是唯一的回路——见 [被挡在门外？](install.md#被挡在门外)

## 扩展

扩展是一个独立程序——有自己的容器或服务、界面和数据库——通过网络与面板协作。
面板从不运行它，也不在自身页面中显示它的页面；面板只保存与它协作所需的信息：
地址、其界面的链接、健康检查路径，以及可能授予它的两样东西——一个 **API 令牌**
和一个 **Webhook**。列表位于 *服务 → 扩展*。

**已签名的扩展**（由 Nexora 发布）通过认领码注册：

1. 启动扩展。它会在日志或自己的页面上显示一个一次性 **认领码**。
2. 点击 *注册已签名扩展*，输入扩展的地址，点击 *读取*。面板会读取其清单，校验
   Nexora 的签名，并显示它请求的内容：令牌的每项权限及原因，以及 Webhook 需要的
   每个事件。
3. 输入认领码，点击 *批准并注册*。面板会创建恰好这些令牌和 Webhook 并交给扩展；
   扩展只在认领码正确时接受。错误的认领码不会留下任何东西。

**自有扩展**——您自己运行的机器人或脚本——手动添加：点击 *添加自有扩展*，填写
名称、地址、入口链接和健康检查路径，并开启 **API 令牌**（选择权限）和/或
**Webhook**（地址下的路径和事件）。保存后令牌和 Webhook 签名密钥**只显示一次**；
请填入您程序的设置。之后可在同一表单中编辑其令牌和 Webhook。

**入口链接。** 您注册的地址是 *面板* 访问扩展的地址——在 Docker 中常常是浏览器无法打开的容器名称。请在扩展所在行通过 *入口链接* 设置浏览器使用的地址；已签名扩展的新版本会保留它。

**地址。** 只有位于本服务器、私有网络或 Docker 网络中的扩展可以使用普通
`http://`。其他情况必须使用带有效证书的 `https://`，因为扩展的令牌会发送到那里。

扩展的令牌和 Webhook 也会出现在 *访问 → API 令牌* 和 *服务 → Webhook* 中，
标记为 *扩展：名称*，且不能在那里删除或编辑。在扩展页面点击 **移除** 会先通知
扩展本身（`panel.addon_removed`），然后删除其令牌和 Webhook。扩展在您的用户旁
存储的数据会保留，因此再次注册时仍能找到。事件 `panel.addon_registered` 和
`panel.addon_removed` 可以发送到 Telegram、邮件或任何 Webhook。

**健康检查。** 扩展有健康检查路径时，面板每分钟请求一次；`200` 表示健康。连续两次
失败会将其标记为 *不健康*，页面显示最后的错误，并发送一次 `panel.addon_unhealthy`；
之后第一次 `200` 会使其恢复并发送 `panel.addon_recovered`。没有健康检查路径的扩展
不会被请求。

**暂停** 会停止扩展而不删除它：其令牌立即失效，其 Webhook 不再接收事件（暂停期间的
事件不会为它保存）。*恢复* 会同时恢复两者。暂停的扩展不会被做健康检查。

**更新。** 面板每小时以及在您点击 *检查更新* 时重新读取已签名扩展的清单。请求的内容
不超过扩展现有授权的新版本会自动应用。请求更多权限或事件的版本会等待：扩展保持现有
授权不变，该行显示 *更新待批准*，发送一次 `panel.addon_update_waiting`，*查看更新*
只列出新增内容及其原因供您批准。请求扩展从未拥有的令牌或 Webhook 的更新无法就地批准；
请移除该扩展并重新注册。
