# 安装 Nexora

Nexora 由一个面板（控制平面）和任意数量的节点（数据平面）组成。本页介绍安装面板。
节点稍后在面板中添加，面板会为每个节点给出一行命令。

安装脚本不会提问。它唯一替你决定的是数据库——而这恰恰是面板事后无法选择的一项，
因为没有数据库，面板根本无处存放设置。其余内容——主管理员、端口、私密路径、
HTTPS——都在你首次打开面板时出现的设置向导中选择。

## 环境要求

- 一台带 systemd 的 64 位 Linux 服务器（Debian 11+、Ubuntu 20.04+、RHEL 9+ 或同类）。
  32 位 ARM 与 x86 同样支持。
- root 权限。
- 一个对外开放的 TCP 端口（默认 2095）。面板绑定的是 IPv6 通配地址，同时也服务
  IPv4，因此仅 v4、仅 v6 或双栈服务器都无需改动即可使用。

## 安装

使用 SQLite，无需任何其他服务：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/nexora-vpn/panel/main/install.sh)
```

使用 PostgreSQL，由安装脚本自动安装并配置：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/nexora-vpn/panel/main/install.sh) --postgres
```

要固定某个版本，追加 `--version v1.2.3`。

面板和节点分别发布，因此版本号也各自独立。安装脚本在安装面板的同时还会准备节点
二进制文件——面板稍后正是把它们交给节点安装脚本；`--node-version v1.2.3` 可以固定
这些文件的版本。不加该参数则取节点的最新发布版本，除非你要复现某个特定的节点集群，
否则这正是你想要的。

SQLite 是合适的默认选项：Nexora 面板的数据量很小，单个文件在备份和迁移时方便得多。
当你已经在运行 PostgreSQL，或面板需要服务大量用户时，再选择 PostgreSQL。这是面板自己
无法事后更改的唯一决定，不过你之后可以通过备份迁移。[选择数据库](database.md) 给出了
阈值、面板在两种数据库上分别替你做的调优，以及迁移步骤。

## 完成设置

安装脚本最后会打印一条链接：

```
http://203.0.113.10:2095/setup?t=9f3c1ad2…
```

打开它。该令牌授权创建主管理员账户，请像对待密码一样对待它，不要贴到公开场合。
设置一旦完成，它立即失效。

在设置完成之前，面板对**其他任何路径都不作应答**：登录页、API、订阅链接一律返回
404，没有令牌时设置页本身同样返回 404。因此公网 IP 上尚未设置的面板不会给扫描器
留下任何线索。

安装脚本会为找到的每个地址各打印一条链接，另外再打印一条使用「互联网看到的本机
地址」的链接。请使用真正能连到服务器的那一条：在 VPS 上通常是公网地址，而在容器
宿主机上，其余大多是通往任何地方的虚拟网桥地址。

IPv6 地址在这些链接里带方括号，这正是 URL 所要求的——
`http://[2001:db8::10]:2095/setup?t=…`。请整条粘贴；没有方括号浏览器不会接受。

如果链接丢失，可在服务器上重新打印令牌，并据此拼出网址：

```bash
nexora-panel setup-token
# → 9f3c1ad2…   然后打开 http://YOUR-SERVER:2095/setup?t=9f3c1ad2…
```

向导在一张表单中收集全部内容，并一次性保存：

- **主管理员** — 配置面板并可查看所有订阅的账户。至少 12 个字符，且包含小写、
  大写、数字、符号中的三类。
- **面板地址** — 监听的 IP 与端口，以及面板响应所用的私密路径。向导会建议一个
  随机路径；保留它意味着扫到你端口的人依然找不到登录页。
- **订阅路径** — 订阅链接基于此路径生成，必须与面板路径不同。
- **HTTPS** — 默认开启。面板会签发自己的证书并在到期前续期。
  - **证书地址**已预填为你打开向导所用的地址，以及本机上所有公网可路由地址。
    请按需修改：面板无从得知你的客户端会使用哪个地址。在容器内它只能看到网桥
    地址，而在 NAT 之后，公网地址根本不在任何接口上——所以如果你在浏览器里输入
    的地址不在列表中，请补上。IPv6 地址直接按原样填写（`2001:db8::10`）；方括号
    也可接受，会被去掉。
  - 添加域名后会重新签发以覆盖该域名，订阅域名也放在同一张证书里。
  - 你可以关闭 HTTPS，但那样密码和订阅链接将以明文传输。
- **时区** — 面板中所有时间按它显示。

保存后面板会重启到你刚刚描述的地址，浏览器随之跳转。使用自签名证书时浏览器会警告
一次，接受后即可继续。

## 怎么在面板里穿行

有两件事值得第一天就知道，因为它们都不在你会去找的地方。

**按 Ctrl-K**（Mac 上是 Cmd-K），或者点击页头的放大镜。一个输入框可以搜索所有
页面、所有“新建…”表单，以及你的用户——按名称、按分组，还有**按订阅 ID**，这把
“客户只发来这条链接”变成一次粘贴。方向键移动，回车打开，Esc 让你回到原来的位置。
在没有输入框聚焦时，单独一个 `/` 也能打开它。

**把面板安装成应用。** 在 Chrome、Edge 或 Android 浏览器里，地址栏会提示安装；
iPhone 上用「分享 → 添加到主屏幕」。之后它会在自己的窗口里打开，没有地址栏，并且
在 `/panel` 这样的基础路径下和在根路径下表现完全一致。它还是同一个面板，只是换了
个外框：没有离线模式，因为控制面板的每一页都是对一支正在变化的机群的实时读取。
安装需要 HTTPS——通过普通 `http://` 打开的面板根本不会给出这个提示。

主色和密度在主题菜单里，就在语言切换旁边：五种配色，以及一个在笔记本屏幕上明显能
多放几行的紧凑模式。两者都属于这个浏览器，而不属于账户。

## 伪装面板

一个隐秘的基础路径，已经能让找到你端口的扫描器找不到登录页。它没能解决的是端口本
身：其余所有地址都返回 404，而一台完成 TLS 握手之后对什么都回 404 的主机，并不是
一台普通服务器。这个信号很小，但恰恰是在没有登录页可找之后仍然留下的那一个。

**设置 → 面板 → 伪装目录** 接受一个绝对路径，这个端口上凡不属于面板、订阅或规则
集镜像的地址，都从该目录当作普通网站提供。`https://panel.example.com/` 会变成你
放进那个目录的内容；面板仍然在它的基础路径上。面板重启后生效。

面板刻意不自带页面。随面板附带的伪装页在所有安装上都会逐字节相同，扫描器只会转而
认这个页面、而不是认那份沉默——那比它替代掉的特征更好认。放点适合这个地址的东西：
一个落地页、一个公司站，或者你本来就会托管的任何内容的副本。

**再放一个 `404.html`。** 该目录下任何没有文件对应的路径都会回 404，而在没有
`404.html` 时，回的是 Go 网页服务器自己的 `404 page not found` 纯文本——扫描器
发出的第一个探测请求就能据此认出这是什么软件，而这正是伪装要抹掉的特征。目录里
有 `404.html` 时就改为提供它，状态码仍是 404。没有它的目录，行为和以前完全一样。

三件它不做的事，每一件都是有意的：

- **它不碰 API。** 面板已经接受的请求属于面板，所以不带凭据的
  `GET /panel/api/users` 依然是 JSON 格式的 401。把认证失败变成网页，会连带弄坏
  所有集成和面板自己的界面。
- **它不列目录，也不提供点开头的文件。** 目录列表是一次读完整个目录的办法，而从
  某台主机上拷下来的目录，十有八九带着 `.git` 或 `.env`。指向目录之外的符号链接
  不会被跟随。
- **没有基础路径时它什么都不做。** 面板在根路径上时，这个地址就没有留给伪装去遮
  盖的部分了。请先设置基础路径。

保存时会拒绝相对路径，也会拒绝 `/`。相对路径会相对于面板自己的工作目录解析，而那
正是它数据库所在的地方。

## Docker

两套编排，各对应一种数据库。选择目录并启动：

```bash
git clone https://github.com/nexora-vpn/panel
cd panel/docker/sqlite      # 或：cd panel/docker/postgres
docker compose up -d
docker compose logs panel | grep setup
```

使用 PostgreSQL 编排时，请在首次启动前把 `.env.example` 复制为 `.env` 并设置密码。

每个编排都把必须比容器活得更久的东西放在其 compose 文件旁边：SQLite 数据库在
`./data`（PostgreSQL 编排改用具名卷），节点二进制在 `./bin`，备份归档在
`./backups`——参见“备份”一节——面板分发给各节点的规则集镜像文件在 `./rulesets`。
最后这个只是缓存：清空它是安全的，面板会在下次启动时重新下载缺失的部分。

在 Docker 中，面板端口由 compose 文件里的 `NEXORA_WEB_LISTEN` 固定，因为端口映射
也在同一个文件里。仅在面板界面改端口只会让容器无法访问，请两处一起改。

`NEXORA_WEB_LISTEN` 绑定的是容器*内部*的地址；真正到达宿主机的是 `ports:` 映射，
而 Docker 若不特别指定只会在 IPv4 上发布。在仅有 IPv6 的宿主机上，请在守护进程中
启用 IPv6（在 `/etc/docker/daemon.json` 中设置 `"ipv6": true` 与
`"ip6tables": true`），并同时在两者上发布：

```yaml
    ports:
      - "0.0.0.0:2095:2095"
      - "[::]:2095:2095"
```

### 面板与节点部署在同一台服务器

`docker/panel-and-node` 就是 SQLite 那套编排，外加一个并排运行的节点。这样做**不
推荐**：节点的地址会写进你分发的每一条订阅链接，因此在这里跑节点等于把面板的地址
公开给所有用户；而客户端流量没有上限，负载中的节点会把面板——以及其他所有节点用户
的订阅——一起拖垮。对于实验环境、演示或小型单服务器部署，这是划算的取舍。完整的注
意事项见[节点安装指南](https://github.com/nexora-vpn/node/blob/main/docs/zh/install.md#面板与节点部署在同一台服务器)。

节点启动前需要面板的客户端证书，而面板只有在其中添加了节点之后才会给出该证书——所
以这套编排分两步启动：

```bash
cd panel/docker/panel-and-node
docker compose up -d panel
docker compose logs panel | grep setup      # 打开链接，完成向导

# 然后在面板中：添加一个地址为 127.0.0.1、端口为 62050 的节点，并把该节点安装页
# 上的客户端证书保存为 ./certs/panel_ca.pem
docker compose up -d node
```

两个服务都使用主机网络——节点是因为其入站所用的端口要在面板中事后选定，面板则是为
了能通过 127.0.0.1 连上节点。这样就没有需要同步维护的端口映射，因此这是唯一*不*固
定 `NEXORA_WEB_LISTEN` 的编排：向导中选择的端口会直接监听在主机上，和原生安装一
样。节点的控制端口也完全不会离开这台机器，无需任何防火墙规则。

## 更新

面板每天检查一次是否有更新的版本，有就显示一条提示条。**设置 → 面板更新**
里是完整的信息：已装版本与最新版本、这台面板是怎么装的，以及——在 systemd
安装上——一个按钮，整套升级由它完成：

1. 先把数据库备份到你的备份目录，
2. 下载该版本，并与随之发布的校验和比对，
3. 把下载到的二进制运行一次，确认它是一个能在这台机器上启动的面板，
4. 换上它，并把旧的保留在 `/opt/nexora-panel/nexora-panel.previous`，
5. 重启。你的登录状态会保留；面板会有几秒无法访问，页面会告诉你它什么时候回来。

如果新版本起不来，之前的二进制会**自动**换回——大约十秒，而不是几分钟。但
**数据库不会回退**：迁移只向前。所以升级后如果哪里不对，回退的办法就是第一步
所做的那份备份，在**设置 → 备份**里。

Docker 安装无法替换自己的镜像，页面会直说，而不是做一半。请按常规方式更新：

```bash
docker compose pull && docker compose up -d
```

每天的检查是向本仓库的发布列表发一个请求，会让 GitHub 知道你服务器的地址。
可以用那个页面上的开关关闭，也可以用命令行：

```bash
nexora-panel config set update_check false
```

关掉之后页面上的按钮依然可用——这个设置管的是面板自己会做什么，而不是你能向
它要求什么。

### 从命令行

再次运行安装脚本。它会识别已有安装并就地更新：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/nexora-vpn/panel/main/install.sh)
```

它会停止服务、把 SQLite 数据库备份为 `nexora.db.bak`、把旧二进制保留在
`/opt/nexora-panel/nexora-panel.previous`、执行迁移，然后重新启动。你的
`config.json`、设置和管理员账户都不会被改动。若使用 PostgreSQL，请自行先做备份。

## 被挡在门外？

所有可能让面板无法访问的设置，都可以在面板未运行时从命令行写入：

```bash
nexora-panel config list                       # 查看已设置的项
nexora-panel config set web_listen_port 2095   # 改成你能访问的端口
nexora-panel config set web_listen_ip ""       # 重新绑定到所有地址（v4 与 v6）
nexora-panel config set web_domain ""          # 取消主机名限制
nexora-panel config set web_basepath ""        # 恢复在根路径提供服务
nexora-panel config set sub_domain ""          # 不再把主机名留给订阅
systemctl restart nexora-panel
```

最后一条是最不容易想到的丢失面板的方式，而且只有在你**没有基础路径**时才会中招。
列在 `sub_domain` 里的域名只提供订阅、别的什么都不提供，好让终端用户的链接不泄露
面板在哪里管理——而当面板位于每个主机名的根路径上时，这就意味着在那些名字上再也
没有地方能够到它。把你实际在用的唯一那些地址填进去（`localhost`、你服务器的 IP），
面板就会一下子从所有地方都打不开。

设置一个基础路径，这个陷阱就消失了：面板在任何主机名上——包括订阅域名——都仍然可
以通过那个前缀访问。拿着链接的客户得先猜出这个前缀，而它本来就是你服务器 IP 上唯
一保护面板的东西。

安装脚本会把 `nexora-panel` 放入 PATH，二进制也会自行找到配置文件，因此这些命令
在任何目录下都可用。在 Docker 中请加前缀 `docker compose exec panel /app/`。

**忘记密码。** 同样是离线的方式，只不过针对的是账号而不是地址：

```bash
nexora-panel admin list                        # 有哪些账号，哪个拥有这个面板
nexora-panel admin reset-password              # 面板所有者；密码是输入的，不会回显
nexora-panel admin reset-password -user alice  # 其他任何账号
```

不带 `-user` 时取面板的**所有者**——那个不可删除、不可降级的账号，`nexora-panel
admin list` 会把它标出来——所以即使有多位主管理员，「主管理员」也只有一个答案。在
早于所有者的旧安装上，命令会退回到「唯一的主管理员」；如果有多个，则拒绝执行并列出
它们的名字。新
密码会要求输入两次，且从不回显；`-pass` 可以一次给出，适合无人值守安装，代价是密
码会留在 shell 历史里。这次重置会做三件事，因为丢失密码和丢失手机是同一种紧急情况：设置密码、**关闭该账号
的两步验证**（密钥和恢复码一并清除，操作员需从面板重新注册），以及**结束该账号所有
打开的会话**。运行中的面板最多会缓存会话一分钟，命令本身会提示这一点；如果这一分钟
很重要，请一并重启面板。

**被封禁挡在门外。** 同一地址连续五次登录失败即被封禁，并且封禁会写入数据库，重启
也不会解除。谁是「这个地址」、谁永远不会被封，由两个设置决定：

```bash
nexora-panel config set trusted_proxies "10.0.0.0/8"   # 你的 nginx / CDN，或留空
nexora-panel config set login_allowlist "203.0.113.7"  # 永不封禁的地址
```

**位于反向代理或 CDN 之后、却没有设置 `trusted_proxies` 的面板，会把所有访客看成同
一个地址** —— 于是第一次封禁就把所有人挡在门外。请把它设为代理的地址，并把你自己的
网络写进 `login_allowlist` 作为退路。主管理员也可以在**设置 → 安全**里解除封禁。

## IPv6

这里没有任何需要配置的东西。面板默认监听 `[::]:2095`，在双栈主机上同样响应 IPv4；
关闭了 IPv6 的主机无法绑定该地址，面板会自行回退到 `0.0.0.0:2095`。若只想绑定其中
一种协议族，可在向导中或用命令行把 `web_listen_ip` 设为一个具体地址（`::` 或
`0.0.0.0`，或者某个特定地址）。

节点是同一个故事的另一面：只有 IPv6 地址的节点，添加时把地址按原样填写即可
（`2001:db8::1`，方括号可选），面板会在语法需要的地方加上方括号——分享链接形如
`vless://…@[2001:db8::1]:443?…`，wireguard 配置形如
`Endpoint = [2001:db8::1]:51820`，而 clash、sing-box 或 OpenVPN 的配置携带的是不
带方括号的地址。基于面板 IPv6 地址生成的订阅 URL 出于同样的原因也会带方括号。

## 你的第一个入站

**入站 → 从预设添加。** 预设就是一种已经定好传输方式和 TLS 决定的协议——
VLESS + REALITY、放在 CDN 后面的 VLESS 或 Trojan over WebSocket、gRPC、
Hysteria2——于是第一个入站变成一次选择加一次保存，而不是四个标签页的抉择。

选中一个预设**什么都不会创建**。它只是把普通的入站表单填好，你确认之后，落到库
里的就是一条普通的入站记录：之后没有任何东西记得它来自哪个预设，所有字段都仍可
编辑。端口、标签和传输路径按安装各自生成；REALITY 的密钥对和 short ID 由面板在
保存时生成——没有哪个密钥需要你去找来粘贴。

这个货架本身是面板提供的一个文件，所以你可以往里加东西。把一个 `.json` 放进
`/var/opt/nexora/presets/`（或者 **设置 → 预设目录** 指向的位置），它就会按 key
合并到内置列表上：新 key 添加，已有 key 替换。把某条规则集条目改指到镜像，在上游
被封的地方，也是同样的做法。解析不了的文件会被跳过并在面板日志里留一行，而不是
把整个目录一起带走；设置页会写出真正生效的文件。

## 路由与 DNS 预设

**模板 → 该模板 → 路由（或 DNS）→ 从预设应用。** 和入站一样的货架思路：一个由面板
已经镜像的列表组成的路由块——拦广告，并把伊朗（或中国、俄罗斯）的域名和地址就在本
节点放出去而不再往下走——以及 DNS 那一侧的一组加密解析器。

应用路由预设会**替换**模板的规则。这是有意的：规则顺序*就是*路由，把你的规则和预
设的规则混在一起，会得到一个谁都没选过的顺序。它需要的规则集是加进当前选择，而不
是替换它。

值得知道的是：当预设需要一个你没有的列表时会怎样。面板会把自己没有副本的规则集排
除掉，**连同每一条匹配它的规则**——不得不如此，因为只要有一条规则引用了未定义的规
则集，节点就会拒绝它的整份配置。所以没带列表就应用的预设，是一个什么都拦不住、也
哪里都不说明原因的模板。对话框会先检查：它会点名缺少的列表并提出在应用前先下载，
而当某个列表连目录也拿不到时，它会直接拒绝。

DNS 预设是 Cloudflare、Google、Quad9 和 AdGuard 的 DNS-over-TLS，外加节点自己的
系统解析器。AdGuard 在解析器层面拦广告，这是拦广告路由预设的替代方案，而不是它的
搭配。

## 链接与订阅

机群跑起来之后，客户实际拿到什么是另一个话题：**[链接与订阅](subscriptions.md)**。
其中讲到一个节点公布多个地址、把 CDN 放到入站前面（包括每客户独立主机名所需的泛
域名 DNS 记录，以及面板为什么拒绝前置 REALITY 或 Hysteria 入站）、用模板命名记录，
还有唯一一个会悄无声息破坏这些配置的客户端开关——基于 Xray 的应用里的 **Mux**。

## 操作员与角色

**设置 → 管理员**用于创建操作员账号，**角色**决定每个账号能做什么。面板自带三个
角色，足以覆盖大多数安装：

| 角色 | 用途 |
| --- | --- |
| 主管理员 | 管理一切，包括面板自身的管理：操作员、角色、API 令牌、许可证、备份与安全设置。 |
| 操作员 | 运营服务：用户、节点、模板、资源池、证书与设置——但不含面板自身的管理。 |
| 代理商 | 只拥有自己的用户簿。流量额度、到期时间与用户上限在账号上设置。 |

**自定义角色**从这三者之一出发，只做减法。它永远无法增加权限：面板会拒绝保存
授予你自己没有的权限的角色，也会拒绝把账号放到这样的角色上。所以「不能碰节点的
操作员」是一个角色，而「还能管理许可证的操作员」不是。

决定一个账号能到达什么的有两件事，它们是不同的问题：

- **权限决定哪些页面。** 没有「配置节点」但有「查看节点」的角色可以打开节点列表，
  而上面的每个按钮都会回答「你的角色缺少 nodes:write 权限」。
- **归属决定哪些用户。** 代理商只看得到自己拥有的账号——这是「身为代理商」的属性，
  不是一项权限。给代理商角色加上「查看用户」，也不会让它看到别人的客户。

角色还可以带**上限**，上限不是权限：该角色的账号最多能拥有多少用户、最多能给用户
设置多大的设备上限、最长能卖多久的套餐。0 表示不限制。角色上限是账号自身额度之上
的天花板，绝不会把额度调高；而完全*没有*设备上限的用户会被拒绝，而不是被悄悄截断
——「不限制」在这里是一个真实的选择，不该替你做主。

编辑角色会把持有该角色的人全部登出，他们在下次登录时拿到新权限。仍被账号使用的
角色无法删除，拒绝信息会列出这些账号，好让你知道去哪里看。三个内置角色始终存在，
不可编辑也不可删除——只能设置它们的上限。

**所有者。** 面板由一个账号拥有。它不可删除、不可降级，也是唯一能把面板交给另一位
主管理员的账号（管理员列表里的皇冠图标）。交接是一次*移交*：你仍是主管理员，但此后
只有新所有者能再次移交。在已有的安装上，所有者是最早的那位主管理员，由系统自动选定
——不需要任何设置。

`nexora-panel admin reset-password` 在没有指定账号名时找的也正是所有者，这也是
`nexora-panel admin list` 会标出它的原因。

## 监控

面板以 Prometheus 格式在 `/metrics` 发布自身数据——哪些节点在线、每个节点的磁盘与
内存、流量、按状态统计的账户、许可证余量、事件总线。**[监控](monitoring.md)** 提供了
一个 compose overlay，把 Prometheus 和 Grafana 放在你的面板旁边并预置好仪表盘，还有
四条值得设置的告警。开始前有两点：该端点需要 API 令牌（它会列出你运行的每个节点），
而且节点没有上报的数值根本不会有序列，而不是一个 0。

## 备份

面板会备份自己的数据库——侧边栏中的 **设置 → 备份**（仅限主管理员：一个归档包含
面板所拥有的全部凭据）。

归档是所有数据表的逻辑导出，装在一个 gzip 压缩的 tar 里，而不是数据库文件的副本。
因此在 SQLite 上取得的归档可以还原到 PostgreSQL，反之亦然；把面板迁移到另一台服
务器，用的也正是它。

```
设置 → 备份
├─ 下载            直接下载到浏览器；服务器上不留任何文件
├─ 在主机上备份    写入下面的备份目录
├─ 计划任务        默认关闭：以小时为单位的间隔，以及保留多少个归档
└─ 检查 / 还原     先查看归档内容，再用它替换数据库
```

**存放位置。** 原生安装为 `/var/opt/nexora/backups`。在 Docker 中，各个 stack 会
把你启动的那个 `docker-compose.yml` 旁边的 `./backups` 挂载进去，因此归档留在宿主
机上，容器被删除也不会丢。无论哪种方式，都请把该目录复制到别处——只存在于它所保护
的那台机器上的备份，不算备份。

**加密。** 口令是可选的，对下载、在主机上取得的备份以及计划任务的备份都生效
（scrypt + AES-GCM）。面板保存它只是为了加密；丢失的口令无法找回，无法解密的归档
也就无法还原——所以请把口令保存在你存放归档的地方，而不是面板上。

**还原前先检查。** *检查* 会在不改动任何东西的前提下读取归档：里面有什么、何时由
哪个面板版本取得，以及有哪些警告——来自另一台主机的归档（其许可证在这里无法通过
校验）、不含主管理员的归档，以及取备份时未包含流量历史或操作日志的归档。

**还原** 会替换数据库中的每一行并重启面板。在此之前，它会把当前数据库的**还原前
快照**写入同一个目录；保留策略永远不会删除这些快照，因此一次事后发现不该做的还
原，可以通过还原该快照来撤销。默认情况下，还原会保留 *本* 安装自己的地址设置
（端口、域名、路径、TLS）和许可证，这样来自另一台机器的归档就不会把面板指向这台服
务器并不具备的地址。

**迁移到另一台服务器。** 在新服务器上安装面板，打开设置链接，在向导的第一屏不要
填表，而是选择 *从另一台服务器迁移？从备份还原*。这是唯一一个在账户尚不存在时也能
还原的地方——而全新安装正处于这种状态；在这里采用的是归档自身的设置，因为空的安装
没有什么值得保留。许可证不会一起迁移：它绑定在主机的硬件指纹上，请在新服务器上安
装你的密钥（`nexora-panel hwid` 会打印所需的指纹）。

**从命令行**配置，适用于无界面或脚本化安装：

```bash
nexora-panel config set backup_enabled true
nexora-panel config set backup_interval_hours 24    # 每天
nexora-panel config set backup_keep 14              # 0 表示全部保留
nexora-panel config set backup_dir /var/opt/nexora/backups   # 必须是绝对路径
nexora-panel config set backup_passphrase "一个足够长的口令"
```

计划设置会在面板的下一次每小时轮询时读取，因此以上命令都不需要重启。
`backup_passphrase` 永远不会被 `config list` 或 `config get` 打印出来。在 Docker
中，请在这些命令前加上 `docker compose exec panel /app/`。

**从命令行还原**，适用于面板根本起不来的情况——数据库丢了，或者面板启动即失败：

```bash
systemctl stop nexora-panel
nexora-panel restore /var/opt/nexora/backups/nexora-backup-20260914-030000.tar.gz
systemctl start nexora-panel
```

它会先把归档读一遍，打印其中的内容和所有警告，然后要求你输入
`replace-database`。没有终端的运行方式——脚本、管道——则用 `-yes` 代替这个确认。
加密归档用 `-passphrase` 提供口令，或者由它询问。和面板里一样，本机自己的地址设置
与许可证会被保留（`-keep-web-settings=false` 和 `-keep-license=false` 则改用归档
里的），并且在任何改动之前都会先写一份还原前快照。

请先停止面板。在 SQLite 上，替换发生在面板下一次启动时，因此仍在运行的面板这期间
写入的内容会留在被替换掉的那个数据库里；在 PostgreSQL 上，数据行会立刻在它脚下被
替换。

## 卸载

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/nexora-vpn/panel/main/install.sh) --uninstall
```

服务与 `/opt/nexora-panel` 会被移除。位于 `/var/opt/nexora` 的数据库*以及备份*会被
刻意保留；确认不再需要时请自行删除——如果这台服务器本身也要下线，请先把
`/var/opt/nexora/backups` 复制走。

## 文件位置

| 路径 | 内容 |
| --- | --- |
| `/opt/nexora-panel/nexora-panel` | 二进制文件 |
| `/opt/nexora-panel/config.json` | 仅数据库连接 |
| `/var/opt/nexora/nexora.db` | SQLite 数据库 |
| `/var/opt/nexora/bin/` | 面板提供给节点安装脚本的节点二进制 |
| `/var/opt/nexora/sub-themes/` | 订阅页面主题 |
| `/var/opt/nexora/presets/` | 预设目录文件，合并到面板自带的目录上 |
| `/var/opt/nexora/backups/` | 备份归档与还原前快照（权限 0700） |
| `/var/opt/nexora/rulesets/` | 面板分发给各节点的规则集镜像文件 |
| `/etc/systemd/system/nexora-panel.service` | 服务单元 |

其余内容——管理员、设置、证书、节点、用户——都存放在数据库中，由面板管理。
