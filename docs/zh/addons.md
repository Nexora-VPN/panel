# 安装扩展

扩展是在面板旁边运行的独立程序：商店、机器人、报表等。面板在
[addons.nexora-panel.org](https://addons.nexora-panel.org) 的**扩展目录**中找到它们，
把它们安装到你的服务器上——通过你自己运行的命令，或由面板经 SSH 自动完成——并在你批准它们的请求后进行注册。
已注册扩展的日常管理（健康检查、暂停、权限更新、移除）见
[面板服务 → 扩展](services.md#扩展)。

## 目录

*服务 → 扩展 → 浏览* 列出目录中的内容。每个扩展属于以下三个级别之一：

| 级别 | 含义 | 安装方式 |
| --- | --- | --- |
| **官方** | 由 Nexora 制作，清单由 Nexora 的密钥签名 | 通过命令或 SSH |
| **已验证** | 来自其他开发者，经 Nexora 审核，由目录担保的密钥签名 | 通过命令或 SSH；同意页面显示开发者名称 |
| **非官方** | 仅经过简单检查后上架 | 只能通过命令安装，卡片和同意页面上有警告 |

面板每天随版本检查读取一次目录，也可以点击*立即读取*。读取的列表由目录自己的密钥签名；
面板会拒绝没有该签名的列表，或比已有列表更旧的列表。如果关闭了每日版本检查（*设置 → 更新*），
目录只在你请求时读取。

## 通过命令安装

选择一个扩展，点击**安装**。表单根据扩展自己的清单生成：

1. **方式**——*作为服务*（其二进制文件由 systemd 运行，无需 Docker）、*使用 Docker*（通过其安装脚本运行其镜像），
   或 *Compose 文件*（适用于只提供 compose 文件的扩展；此时 HTTPS 回答不能是 `acme-http`，因为没有为 CA 发布 80 端口）。
2. **面板访问它的地址**——扩展运行后从本面板看到的地址。普通 `http://` 只能用于私有地址。扩展的 HTTPS 回答开启时，表单会建议其公开地址加上管理路径：面板就在那里通过 HTTPS 访问它。
3. **它访问面板的地址**——从扩展所在服务器看到的本面板地址。
4. **安装问题**——端口、数据库、令牌：完全是扩展声明的内容，每项都有自己的类型。依赖其他问题的问题只在适用时显示。管理员密码须为 10 个字符至 72 字节（约 36 个波斯文或俄文字母，24 个汉字）；表单会提示这一点，通过命令安装时 `install.sh` 也会拒绝超出该范围的密码。

**生成命令**会检查回答，生成一次性认领码，并给出一条需要**在扩展所在服务器上以 root 身份运行**的命令。
如果某个回答是密钥，命令中会包含它，且只显示这一次——关闭前请复制。面板从不保存你的回答。

然后面板等待扩展在其地址上响应。响应后，面板会显示扩展请求的内容——令牌的每项权限及理由、每个事件——
点击**批准并注册**即可用面板已有的认领码完成注册，无需回传任何内容。在此期间可以关闭表单：
该安装会在*等待扩展响应*中保留一周，并带有**继续**按钮。

没有本面板信任的签名的扩展，会进入已填好字段的*添加自有扩展*：你需要在那里自己创建它的令牌和 webhook。

## 通过 SSH 安装

对于官方或已验证的扩展，**由谁运行**还提供*面板通过 SSH* 选项——与面板安装节点的方式相同：

- **服务器**、**SSH 端口**、**用户**（root，或有 sudo 权限的用户），以及**密码**或**私钥**。
  它们只用于本次连接，不会保存。服务器的主机密钥在首次连接时记住。
- **发布文件**——*由面板提供*：面板下载发布文件，用该发布的 `SHA256SUMS` 校验后上传，因此服务器无需访问 GitHub。
  *由服务器下载*：安装脚本在服务器上自行下载发布文件。
- **在此服务器上授权面板的密钥**——以后更新和移除无需密码。不开启的话，每次都会再次询问。

**安装**会在服务器上运行扩展的安装脚本，并实时显示日志。随后扩展按上述方式注册：查看后点击**批准并注册**。
要安装到面板自己的服务器上，见[在面板自己的服务器上](#在面板自己的服务器上)；面板运行在 Docker 中时，它所在的主机只是另一个 SSH 目标。

面板会先检查服务器（架构、systemd 或 Docker），如果扩展无法在那里运行，会在写入任何内容之前停止并说明原因。

## 在面板自己的服务器上

当面板直接运行在 Linux 服务器上（不在 Docker 中）时，**由谁运行**会首先提供并选中*面板，在本服务器上*：面板以 root 身份自己运行扩展的安装脚本，无需 SSH，也无需输入任何内容。
发布与通过 SSH 安装时一样，按其签名的 `SHA256SUMS` 进行校验，**面板访问它的地址**会自动填为 `http://127.0.0.1:<port>`——扩展的 HTTPS 开启时则填为其公开地址。
运行在 Docker 中的面板不提供此选项——它会把扩展装进自己的容器——并会说明原因；在那里请通过命令或 SSH 安装。

通过 SSH 安装在面板自己服务器上的扩展，可通过**在其服务器上更新** → *此主机就是面板所在的服务器：在此运行，无需 SSH* 转为这种安装。对任何其他服务器，面板都会拒绝。

在面板的服务器上，扩展的 HTTPS 证书来自面板（见下文）：扩展自己的 ACME 证书需要面板或节点已占用的 80 或 443 端口，因此表单在那里不提供该选项。

## 来自面板的证书

HTTPS 回答中提供 **panel** 的扩展（Shop 和通知扩展都提供）会用面板自己证书库（*证书*）中的证书提供其公开地址。
面板负责签发和续期；扩展每隔几分钟从面板获取一次（注册前凭领取码，注册后凭令牌）并保留一份副本，因此即使面板停机，它也能以 HTTPS 启动。
它无需自己的 ACME，因此可以监听任何端口，多个扩展可与面板共用一台服务器。

- 在安装表单中，选择 **HTTPS 证书：panel** 并选定证书。*在证书页面创建一个*会在新标签页中打开证书库；创建后重新加载列表。
- 对其他服务器上的扩展，只提供 **dns-01** 签发、**自签名**或**上传**的证书：http-01 和 tls-alpn-01 证明的是面板的服务器，而不是扩展的。面板自己的 HTTPS 证书，无论由何种方式签发，都不会提供给这样的扩展：其密钥会让那台服务器冒充面板。每次获取时都会重新检查，因此后来成为面板自身证书或改用 http-01 重新签发的证书，将不再发给此类扩展——它会保留手上的副本直到过期；请在其所在行另选一张。
- 扩展只在安装时的**端口**上提供 HTTPS，旁边不再有单独的明文 HTTP 端口，公开地址必须包含这个端口（未写端口即 443）：在 443 已被占用的地方，端口填 8443，公开地址填 `https://shop.example.com:8443`。表单和 `install.sh` 会拒绝端口不一致的公开地址。在 Docker 中，compose 按原样发布该端口。
- 之后可在扩展的行上更改或清除：**证书**。
- 面板通过 https 访问扩展时，会信任它发给该扩展的自签名证书；浏览器会像对待任何自签名证书一样给出警告。

其他回答保持不变，同样只用这一个端口：**acme**（扩展获取自己的证书，并在自己的端口上应答 CA，因此端口必须是 443——`install.sh` 会拒绝其他端口，此时请选择 acme-http 或 panel）、**acme-http**（同上，可用任意端口，CA 在 80 端口验证，80 端口仅在此模式下发布）、**self-signed**（见[下文](#扩展自己的证书)）和 **off**（在该端口上提供明文 HTTP，供你自己的反向代理使用）。此前安装的扩展在更新后保留原来的两个端口，无需任何操作。

## 扩展自己的证书

使用 **self-signed** 时，扩展提供的是它自己生成的证书，既没有 CA 也没有面板为它担保。面板会在同意页面显示该证书的 SHA-256 指纹并给出警告：请将它与扩展“设置”页显示的指纹核对；批准即信任这一张证书。

扩展大约每年续期一次（证书有效期 397 天，在到期前 30 天续期）。续期后面板不再信任它——健康检查失败，并提示证书不受信任；手动添加的扩展从一开始也是这种状态。在扩展所在行的菜单中，**证书**会显示**当前提供的证书**及其指纹；核对后点击**信任此证书**。

对于以 IP 访问的地址，选择 **panel** 并使用面板证书库中的自签名证书则无需这些步骤：面板信任它自己的证书。

## 更新

当目录中有已注册扩展的新版本时，它在*已注册*标签页中的行会显示出来（*目录中为 0.2.0*），扩展菜单上也会出现一个圆点。

- **通过 SSH 或在本服务器上安装的：**点击**在其服务器上更新**，会在同一台服务器上再次运行安装脚本。设置和数据都会保留，面板会立即读取新的清单。
- **通过命令安装的：**在其服务器上不带参数再次运行安装脚本：`sh nexora-addon-install.sh` 会以同样方式安装最新发布，并保留回答和数据。
  对于 *Compose 文件* 安装，把 `.env` 中的 `NEXORA_ADDON_VERSION` 改为新版本，然后运行
  `docker compose pull && docker compose up -d`。

请求更多权限或事件的新版本会被安装，但在你批准之前不会获得这些权限——见[更新](services.md#扩展)。

## 移除

**从其服务器移除**（适用于通过 SSH 或在本服务器上安装的扩展）会在同一台服务器上以 `--uninstall` 运行安装脚本；
勾选*同时删除其数据*会一并删除其数据目录——此操作无法撤销。扩展在面板中仍保持注册状态，
直到你在面板中也点击**移除**；在面板中移除会先通知扩展本身，再删除它的令牌和 webhook。

手动操作，在扩展所在服务器上：

```sh
sh nexora-addon-install.sh --uninstall           # 保留数据
sh nexora-addon-install.sh --uninstall --purge   # 同时删除数据
```

保留数据移除、随后又从面板重新安装（新的安装、新的认领码）的扩展，会像其他扩展一样正常注册：它发现认领码是新的，就丢弃之前保留的注册，把管理员密码设为新安装给出的密码，关闭其两步登录，并结束其所有会话。更新和重启则两者都保留。较旧版本的扩展会改为回答 *already registered*（409）；面板会说明该怎么做：从面板重新安装，或先连同数据一起移除。

## 目录镜像

如果无法访问 addons.nexora-panel.org，可以在*浏览*标签页中点击**更改来源**，让面板指向其 `index.json` 的副本。
任何副本都是安全的：面板会校验其上的目录签名，因此镜像可以提供列表，但无法篡改。留空则恢复为 addons.nexora-panel.org。
通过 SSH 并选择*由面板提供*时，发布文件经由面板从 GitHub 获取，因此只有面板本身需要访问 GitHub。
