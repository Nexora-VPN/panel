# 隧道

隧道把您的两个节点连起来：用户连接其中一个，即 **中继**，流量则从另一个节点，即
**出口**，进入互联网。用途：

- **好入口，另一个出口。** 用户连接其网络容易到达的服务器——离他们近、线路好的机房、
  未被封锁的地址——而流量从别处的服务器出去。
- **不接受任何连接的出口。** 默认模式下由出口节点主动连接中继，所以它在 NAT 之后、
  或所有入站端口都关闭时也能工作，用户永远看不到它。
- **一个入口后面多个出口。** 一个中继可以带一条通往多个出口的隧道。

## 隧道如何工作

- **中继** 是用户连接的地方，通过它所在模板的普通入站——用户和他们的链接都不变。
  中继原本要发往互联网的流量，改为送进隧道。
- **出口** 是这些流量进入互联网的地方。在出口节点上，流量经过该节点自己的路由，
  和到达那里的任何流量一样。
- **每个用户固定在一个出口上**，只要该出口在线，所以他的出口地址不会每次连接都变——
  这样网站不会把他登出，也不会每次都要验证码。某个出口掉线时，只有原本在它上面的
  用户会换到别的出口。
- **TCP 和 UDP** 都能通过。
- **隧道不影响其他任何东西。** 它有自己的端口和自己的凭据（每个出口一份），由面板
  推导、从不存储——没有需要复制的东西，两端也不会对不上。不占用任何入站，不为它
  创建账户，用户流量仍在他们连接的地方，也就是中继上计算。
- **变更实时下发到节点。** 创建、编辑、停用或删除隧道都不会重启任何一个节点的核心。

一个节点可以是一条隧道的中继、同时是另一条隧道的出口，所以中继链是可行的。但在
*同一条* 隧道里，一个节点不能既是中继又是出口。

## 开始之前

1. **两个节点都已添加并连上**（**节点** 页面）。
2. **中继在为用户服务**：它在一个有入站的模板上，用户也在这个模板上。隧道只改变
   中继的流量从哪里出去，并不会让节点开始为谁服务。
3. **监听端有对方能到达的地址。** 拨号端会拨监听节点的 **链接地址**（节点 → 编辑），
   全部同时拨、互为备份；没有链接地址时拨它的 **地址**。监听节点两者都没有时，面板
   拒绝保存。
4. **端口空闲且已放行。** 每条隧道在监听节点上占用自己的端口（默认 `8443`）。该节点
   上已被入站或其他隧道占用的端口会被拒绝。如果服务器有防火墙，请在防火墙里放行
   该端口——面板不会替您做。
5. **先升级面板，再升级节点**，和每次发布一样。有多个 [配置档](#配置档) 的隧道需要
   当前版本的节点；旧节点只读取一个。

## 反向还是正向

模式只决定哪一端开端口。两种模式下流量方向相同：用户 → 中继 → 出口 → 互联网。

| | 反向（默认） | 正向 |
| --- | --- | --- |
| 谁监听 | 中继 | 每个出口 |
| 谁拨号 | 每个出口拨中继 | 中继拨每个出口 |
| 需要放行端口的是 | 中继 | 所有出口 |
| 出口在 NAT 后或完全被防火墙挡住 | 可以 | 不行 |
| 何时选 | 几乎总是 | 中继无法接受来自出口的连接，但可以主动连出去时 |

表单会用一句话、带上您的节点名，说明这条隧道将怎么工作。

## 创建隧道

**隧道 → 添加隧道。**

| 字段 | |
| --- | --- |
| 名称 | 成为隧道的 **标签**：`tunnel-` 加上名称的小写拉丁字母和数字（空格、点和下划线变成 `-`，其他字符被丢弃）。没有拉丁字母或数字的名称——例如中文名——得到 `tunnel-t<id>`。最多 48 个字符，**保存后不能修改**：标签和两端的凭据都由它生成。会得到相同标签的两个名称（`eu west` 和 `eu-west`）会被拒绝。 |
| 模式 | [反向或正向](#反向还是正向) |
| 中继节点 | 用户连接的地方 |
| 出口节点 | 一个或多个；流量进入互联网的地方 |
| 每个出口的链路数 | 每个出口保持多少条并行连接；默认 4，最多 64。每条都有自己的拥塞窗口，所以一个丢包只拖慢那条连接上的流。4 几乎适合所有线路。 |
| 单流窗口 | 一个连接最多可以有多少数据在途；留空为 4 MiB，否则在 256 KiB 到 1 GiB 之间。只有当长距离线路上单个下载很慢、而多个一起很快时才调大。 |
| 已启用 | 停用的隧道会从两个节点上移除，设置保留 |

下面是隧道的第一个 **配置档**：**监听端口**，以及 **安全**、**传输**、**高级** 三个
标签页。新隧道默认使用 REALITY，无需填写任何东西；点 **保存**，它就在两个节点上了。

## 安全与传输

**安全**——保护两个节点之间连接的方式：

- **REALITY**（默认）让连接看起来像是到某个知名网站的普通 TLS 连接，不需要证书。
  私钥和 Short ID 在保存时生成；握手网站可以更换。
- **TLS**——面板为隧道自己的名称（`<name>.tunnel.internal`，一个在哪里都解析不到的
  名称；连接仍然发往节点地址）签发证书，另一端固定（pin）这张证书。不用购买，也不用
  续期：有效期十年。要用自己的证书，请以 PEM 粘贴证书和私钥两者；只有一半，或节点上
  的文件路径，都会被拒绝。
- **不加密**——连接是明文。令牌仍然能挡住陌生人，但用户发送的一切在两个节点之间
  明文传输。

**传输**——可选，把连接包装成看起来像网页请求，而不是一条无法识别的长连接：
**WebSocket**、**gRPC**、**HTTP**、**HTTPUpgrade** 或 **QUIC**。QUIC 自带 TLS，所以
需要在安全标签页选 **TLS**，且不能与 REALITY 一起用；表单和面板都会拒绝这些组合。

**高级** 按节点收到的原样显示 TLS 和传输两个配置块。在这里编辑会覆盖上面的标签页。

## 配置档

配置档是承载隧道的一种方式：自己的端口、自己的安全设置、自己的传输。*新增一种承载
方式*（配置档标签旁的 **+**）再加一个，最多八个。它们不是独立的隧道：它们的连接
在相同的出口下共用一个连接池，所以 **某个协议被封只损失吞吐，不损失隧道**——也不会
改变用户的出口地址，不管走的是哪个配置档，用户都留在同一个出口。

常见的组合：一个端口用 REALITY，另一个端口用 WebSocket over TLS。

有两个或更多配置档时会多出两项设置：

- **负载均衡**——**分摊**：所有已连接的配置档都承载流量，新连接选最空闲的那个。
  **优先级**：列表中第一个已连接的配置档承载全部流量；只有它一条连接都没有时才用
  下一个——是备用路径，而不是额外容量。
- **此配置档的链路数**——该配置档承担的负载份额。连接分布在各条链路上，所以六条链路
  的配置档对两条链路的配置档，承载三倍流量。留空则取 *每个出口的链路数*。

每个配置档都需要自己的端口，与其他配置档、监听节点上的所有入站以及该节点上的其他
隧道都不同。

## 中继的流量去哪里

**当中继只承载一条隧道时，这条隧道就是中继的默认出口**——面板自动把该节点的 *final*
出站设为隧道的标签。列表中的 **默认出口** 列会显示是否如此。模板路由里的规则在中继上
仍然先生效，所以把部分流量发往 `direct` 或拦截它的规则在那里照样起作用。

**千万不要把隧道标签写进模板的路由。** 只有中继有这个标签；模板上的其他节点会收到
一个指向它们没有的出站的路由，它们的核心将无法启动。

以下情况面板不选出口，并在默认出口列里说明原因：

- **中继承载不止一条隧道**——哪些流量走哪条，由您决定；
- **中继有自己的 final**——节点自己的路由总是优先。

这两种情况下，以及只想让 *部分* 流量走隧道时，请写在中继自己的路由里：
**节点 → 配置 → 路由（本节点覆盖）**。这里的规则追加在模板规则之后，并且可以引用
隧道标签，因为它们只下发到中继。例如一个承载两条隧道的中继：

```json
{
  "rules": [
    { "rule_set": ["geosite-netflix"], "outbound": "tunnel-exit-us" }
  ],
  "final": "tunnel-exit-de"
}
```

这里引用的规则集必须已在中继的模板中选中。节点菜单里的 **路由测试** 会显示某个地址
会命中哪条规则、走向哪里。

## 状态与实时状态

**列表** 打开后会询问每条隧道的两端——隧道的状态无法从配置中看出：

| 状态 | 含义 |
| --- | --- |
| *n* 个连接 | 正常；有 *n* 条连接在线 |
| 没有连接 | 中继有响应，但没有出口连上它——见 [下文](#连不上时) |
| 中继不可达 | 面板连不上中继节点 |
| 未知 | 检查失败；这并不说明隧道本身怎样 |

列表上方的统计条按同样的状态计数；点其中一项只显示这些行。*刷新状态* 重新检查。

行菜单中的 **实时状态** 会询问隧道的所有节点，打开期间每隔几秒自动刷新：每个出口的
连接、流和在线时长；拨号端还显示期望的连接数、距下次重试的时间（*重试退避*）以及
**最近错误**。

该对话框里的 **重置** 会在所有节点上重建隧道：所有连接断开，拨号端立即重新开始。
当某一端在线却不承载任何流量，或者封锁已解除、拨号端却还在每次等满一分钟再重试时
使用。隧道上的流量会中断，直到重新连上。

行菜单中的 **流量图表** 显示经过这条隧道的流量。

## 每个中继一条隧道

多个中继通往同一组出口，应是 **每个中继一条隧道**，而不是一条隧道带多个中继。这样
从一个中继上泄露的凭据在另一个中继上毫无用处，新增中继也只是新建一条隧道，而不必
改动正在承载流量的隧道。

- 行菜单中的 **创建副本** 会询问名称和中继，并复制出口、配置档和设置。证书和密钥
  *不会* 复制：副本会得到自己的。
- **选中多行** 后可用 *编辑所选…*——一次性为它们设置出口、每个出口的链路数、单流窗口
  或负载均衡；留空的字段保持不变——以及 *启用*、*停用*、*重置* 和 *删除*。

删除节点会把它从所在的所有隧道中移除。失去中继或失去最后一个出口的隧道会随之删除，
审计日志会记录这一点。

## 连不上时

打开 **实时状态**，先看 **最近错误**。然后检查：

- **防火墙**——监听端口在监听节点上已放行：*反向* 模式是中继，*正向* 模式是所有出口。
  在另一个节点上测试：`nc -vz <address> <port>`。
- **地址**——拨号端使用监听节点的链接地址，没有时用它的地址。只有面板能到达的地址
  （内网或管理地址）对另一个节点没用；请把公网地址填进链接地址。
- **链接地址中的 CDN 地址** 也会被拨。如果隧道无法穿过那个 CDN，该地址只是一直处于
  退避中，隧道由其他地址承载。
- **REALITY 的握手网站** 必须能从监听节点访问，并支持 TLS 1.3。
- **封锁解除后**，直接点 *重置*，不必等下一次重试。
- **模式**——在 NAT 后的出口只能用 *反向* 模式。
