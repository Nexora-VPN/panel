# Установка дополнений

Дополнения — это отдельные программы, работающие рядом с панелью: магазин, бот,
отчёт. Панель находит их в **каталоге дополнений** на
[addons.nexora-panel.org](https://addons.nexora-panel.org), устанавливает на ваш
сервер — командой, которую вы запускаете сами, или сама по SSH — и регистрирует
после того, как вы одобрите то, что они запрашивают. Как обслуживать
зарегистрированное дополнение (проверка работоспособности, приостановка,
обновление прав, удаление), описано в
[Сервисы панели → Дополнения](services.md#дополнения).

| | |
| --- | --- |
| [Каталог](#каталог) | что в нём есть и насколько доверять каждому дополнению |
| [Установка командой](#установка-командой) | панель даёт одну команду для запуска |
| [Установка по SSH](#установка-по-ssh) | панель сама устанавливает дополнение на сервер |
| [На сервере самой панели](#на-сервере-самой-панели) | панель ставит его рядом с собой, без SSH |
| [Сертификат от панели](#сертификат-от-панели) | HTTPS для дополнения без своего порта 443 |
| [Обновление](#обновление) | значок и обновление там, где дополнение работает |
| [Удаление](#удаление) | с его сервера и из панели |

## Каталог

*Сервисы → Дополнения → Каталог* показывает содержимое каталога. Каждое
дополнение относится к одному из трёх уровней:

| Уровень | Что это значит | Как можно установить |
| --- | --- | --- |
| **Официальное** | сделано Nexora, манифест подписан ключом Nexora | командой или по SSH |
| **Проверенное** | от другого разработчика, проверено Nexora, подписано ключом, за который ручается каталог | командой или по SSH; экран согласия называет разработчика |
| **Неофициальное** | размещено только после беглой проверки | только командой, с предупреждением на карточке и на экране согласия |

Панель читает каталог раз в день вместе с проверкой выпусков и по кнопке
*Прочитать сейчас*. Список подписан собственным ключом каталога; панель
отвергает список без этой подписи или более старый, чем уже имеющийся. Если
ежедневная проверка выпусков выключена (*Настройки → Обновление*), каталог
читается только по запросу.

## Установка командой

Выберите дополнение и нажмите **Установить**. Форма строится по манифесту самого
дополнения:

1. **Способ** — *Как служба* (его бинарный файл под systemd, без Docker), *С
   Docker* (его образ, через скрипт установки) или *Файл compose* (для
   дополнения, у которого есть только файл compose).
2. **Адрес, по которому панель его достанет** — адрес дополнения после запуска,
   как его видит эта панель. Простой `http://` — только на частном адресе.
3. **Адрес панели для дополнения** — адрес этой панели, как его видит сервер
   дополнения.
4. **Его вопросы** — порт, база данных, токен: ровно то, что объявляет
   дополнение, каждое со своим типом. Вопрос, зависящий от другого, появляется
   только когда он нужен.

**Получить команду** проверяет ответы, создаёт одноразовый код привязки и
выдаёт одну команду, которую нужно выполнить **от root на сервере
дополнения**. Если один из ответов — секрет, команда содержит его и
показывается только один раз: скопируйте её перед закрытием. Панель нигде не
хранит ваши ответы.

Затем панель ждёт, пока дополнение ответит по своему адресу. Когда оно
ответит, панель покажет, что оно запрашивает — каждое право токена с
объяснением и каждое событие, — а **Одобрить и зарегистрировать** зарегистрирует
его с кодом привязки, который у панели уже есть: ничего копировать обратно не
нужно. Форму можно закрыть: установка останется в разделе *Ожидают ответа
дополнения* с кнопкой **Продолжить** на неделю.

Дополнение без подписи, которой доверяет эта панель, приводит к *Добавить своё
дополнение* с заполненными полями: токен и вебхук вы создаёте там сами.

## Установка по SSH

Для официального или проверенного дополнения в поле **Кто запускает** есть
вариант *Панель, по SSH* — так же, как панель устанавливает узел:

- **Сервер**, **Порт SSH**, **Пользователь** (root или пользователь с sudo) и
  **пароль** или **закрытый ключ**. Они используются только для этого
  подключения и не сохраняются. Ключ сервера запоминается при первом
  подключении.
- **Файлы выпуска** — *Приносит панель*: панель скачивает выпуск, сверяет его с
  `SHA256SUMS` выпуска и загружает на сервер, так что серверу не нужен доступ к
  GitHub. *Скачивает сервер*: скрипт установки скачивает выпуск на самом
  сервере.
- **Авторизовать ключ панели на этом сервере** — чтобы последующие обновление и
  удаление не требовали пароля. Если не включать, пароль будет спрашиваться
  каждый раз.

**Установить** запускает скрипт установки дополнения на сервере и показывает
его журнал в реальном времени. Затем дополнение регистрируется, как описано
выше: просмотр и **Одобрить и зарегистрировать**. Чтобы установить на сервер
самой панели, см. [На сервере самой панели](#на-сервере-самой-панели); когда
панель работает в Docker, её сервер — просто ещё одна цель SSH.

Сначала панель проверяет сервер (архитектуру, systemd или Docker) и, если
дополнение там не запустится, останавливается с объяснением, ничего не
записав.

## На сервере самой панели

Когда панель работает прямо на сервере Linux (не в Docker), в **Кто
запускает** первым стоит и выбран вариант *Панель, на этом сервере*: панель
сама запускает скрипт установки дополнения от root, без SSH и без ввода
чего-либо. Выпуск проверяется по подписанному `SHA256SUMS` так же, как по SSH,
а **Адрес, по которому панель его достанет** заполняется как `http://127.0.0.1:<port>`. Панель в
Docker этого не предлагает — она установила бы дополнение в свой контейнер — и
объясняет почему; там ставьте командой или по SSH.

Дополнение, установленное по SSH на сервер самой панели, переходит на такую
установку через **Обновить на сервере** → *Этот хост и есть сервер панели:
выполнить здесь, без SSH*. Для любого другого сервера панель это отклоняет.

На сервере панели дополнение берёт сертификат HTTPS у панели (ниже): своему
сертификату ACME нужен порт 80 или 443, который уже занят панелью или нодой,
поэтому форма там его не предлагает.

## Сертификат от панели

Дополнение, чей ответ HTTPS предлагает **panel** (Shop и уведомитель
предлагают), обслуживает свой публичный адрес сертификатом из хранилища самой
панели (*Сертификаты*). Панель выпускает и продлевает его; дополнение раз в
несколько минут забирает его у панели (до регистрации — по коду, после — по
токену) и хранит копию, так что поднимается с HTTPS, даже когда панель
недоступна. Своё ACME ему не нужно, поэтому оно слушает любой порт, и
несколько дополнений делят один сервер с панелью.

- В форме установки ответьте **Сертификат HTTPS: panel** и выберите
  сертификат. *Создать на странице сертификатов* открывает хранилище в новой
  вкладке; после создания обновите список.
- Для дополнения на другом сервере предлагаются только сертификаты **dns-01**,
  **самоподписанные** или **загруженные**: http-01 и tls-alpn-01 доказывают
  сервер панели, а не дополнения.
- Где 443 занят, дайте публичному адресу свой порт, например
  `https://shop.example.com:8443`: дополнение обслуживает HTTPS на порту из
  адреса.
- Позже его можно сменить или убрать в строке дополнения: **Сертификат**.
- Самоподписанному сертификату, выданному дополнению, панель доверяет, когда
  обращается к нему по https; браузеры предупреждают, как для любого
  самоподписанного.

Остальные ответы остаются: **acme** (дополнение получает свой на порту 443),
**acme-http** (то же, CA проверяет на порту 80 — для отдельного сервера, где
443 занят), **self-signed** и **off**.

## Обновление

Когда в каталоге появляется более новая версия зарегистрированного
дополнения, его строка на вкладке *Зарегистрированные* показывает это (*0.2.0 в
каталоге*), а в меню дополнений появляется точка.

- **Установлено по SSH или на этом сервере:** **Обновить на сервере** снова запускает скрипт
  установки на том же сервере. Настройки и данные сохраняются, а панель сразу
  читает новый манифест.
- **Установлено командой:** на его сервере снова запустите скрипт установки
  без аргументов: `sh nexora-addon-install.sh` установит последний выпуск тем
  же способом, сохранив ответы и данные. Для установки через *Файл compose*
  поменяйте `NEXORA_ADDON_VERSION` в `.env` на новую версию и выполните
  `docker compose pull && docker compose up -d`.

Новая версия, запрашивающая больше прав или событий, устанавливается, но
получает их только после вашего одобрения — см.
[обновления](services.md#дополнения).

## Удаление

**Удалить с сервера** (для дополнения, установленного по SSH или на этом сервере) запускает скрипт
установки с `--uninstall` на том же сервере; отметьте *Удалить и данные*, чтобы
удалить и каталог данных — это необратимо. Дополнение остаётся
зарегистрированным в панели, пока вы не нажмёте там **Удалить**; удаление в
панели сначала уведомляет само дополнение, затем удаляет его токен и вебхук.

Вручную, на сервере дополнения:

```sh
sh nexora-addon-install.sh --uninstall           # данные сохраняются
sh nexora-addon-install.sh --uninstall --purge   # данные тоже удаляются
```

## Зеркало каталога

Если addons.nexora-panel.org недоступен, направьте панель на копию его
`index.json` кнопкой **Изменить источник** на вкладке *Каталог*. Любая копия
безопасна: панель проверяет на ней подпись каталога, поэтому зеркало может
отдавать список, но не может его изменить. Пустое значение возвращает
addons.nexora-panel.org. При установке по SSH с *Приносит панель* файлы выпуска
идут с GitHub через панель, так что доступ к GitHub нужен только самой панели.
