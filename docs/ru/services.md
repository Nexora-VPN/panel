# Сервисы панели

Меню **Сервисы** на боковой панели (только главный администратор) — это то, через
что панель общается с внешним миром: уведомления в Telegram и по почте, копии каждой
резервной копии в другом месте и вход с учётной записью, которая у вас уже есть в
Google, Microsoft, GitHub или на вашем собственном сервере идентификации. Там же
находятся вебхуки.

| | |
| --- | --- |
| [Выключено, пока не включите](#выключено-пока-не-включите) | что общего у всех сервисов |
| [Telegram](#telegram) | уведомления в чат и несколько команд только для чтения |
| [Почта](#почта) | те же уведомления по почте |
| [Хранилища бэкапов](#хранилища-бэкапов) | S3-совместимое хранилище, SFTP, чат Telegram |
| [Единый вход](#единый-вход) | кнопка входа для каждого провайдера |
| [Дополнения](#дополнения) | отдельные программы, которые регистрирует панель |

## Выключено, пока не включите

Каждый сервис изначально выключен, а выключенный сервис ничего не запускает и не
открывает ни одного соединения. У каждого — карточка из одних и тех же частей:

- **Сервис включён** — переключатель.
- **Его настройки.** Пароль, токен или ключ после сохранения больше не показывается:
  в поле написано *Задан — оставьте пустым, чтобы сохранить*. Пустое поле сохраняет
  то, что уже записано.
- **Проверить** — проверяет *сохранённое*, поэтому сначала сохраните.
- **Последний запуск** — когда сервис последний раз что-то делал, и последняя ошибка,
  если не получилось.

Настройки сервисов хранятся в базе данных, как и все остальные учётные данные панели,
а значит, попадают в каждую резервную копию — ещё одна причина задать пароль копий.

## Telegram

**Сервисы → Telegram.** Панель отправляет уведомления — у клиента заканчивается срок
или трафик, нода недоступна, резервная копия не удалась — в чаты Telegram, каждый из
которых привязан к одной учётной записи панели. Чат получает только то, что может
видеть его учётная запись: **чат реселлера слышит только о его собственных клиентах.**

**1. Создайте бота.** Напишите в Telegram **@BotFather**, отправьте `/newbot` и
вставьте выданный токен в поле **Токен бота**. Заведите для панели отдельного бота:
во время привязки чата панель читает сообщения бота, и другая программа, читающая того
же бота, заберёт их раньше.

**2. Если панель работает в Иране,** `api.telegram.org` оттуда недоступен. Заполните
одно из двух:

- **Прокси** — `socks5://host:port` или `http://host:port` (логин и пароль — в самом
  адресе: `socks5://user:pass@host:port`).
- **Адрес Bot API** — [сервер Bot API](https://github.com/tdlib/telegram-bot-api),
  запущенный вами за пределами страны, вместо прокси.

Включите сервис, сохраните и нажмите **Проверить**.

**3. Привяжите чат.** *Привязать чат*, выберите учётную запись, язык уведомлений и
события, которые чат должен получать, затем *Получить код*. Окно покажет:

- ссылку и QR-код — откройте на телефоне, который должен получать уведомления, и
  нажмите **Start**;
- сам код, чтобы отправить его боту вручную;
- для **группы**: *Добавить бота в группу* — вы выбираете группу, и код отправляется
  туда сам, или строку `/start@yourbot CODE` для группы, где бот уже есть. В группе бот
  слышит только команды, адресованные ему по имени, поэтому отправленный туда голый
  код он не увидит.

Код действует десять минут. Каждая учётная запись может привязать и свой собственный
чат из своего меню (**Мой Telegram**) — реселлеру для этого не нужен главный
администратор.

**События.** *Всё, что может видеть этот аккаунт* включает и события, которые
добавят будущие версии. Снимите галочку, чтобы выбрать вручную; событие, которое
учётная запись видеть не может, серое и в её чат никогда не попадёт. Недоступный чат
получает повторные попытки, как вебхук, поэтому уведомления, отправленные во время
сбоя Telegram или прокси, придут, когда связь вернётся.

**Доставки** в строке чата показывают каждое отправленное в него уведомление —
доставлено, ждёт повтора или брошено — с ответом Telegram и кнопкой
*Отправить снова* для любого из них. Каждая учётная запись видит доставки своих
чатов в **Мой Telegram**.

**Команды.** В привязанном чате:

| Команда | Ответ |
| --- | --- |
| `/status` | сводка: учётные записи по состоянию и сколько онлайн (реселлер — только свои), а для главного администратора и операторов — ноды |
| `/user name` | одна учётная запись: трафик, срок, онлайн (реселлер — только свои) |
| `/node name` | одна нода (главный администратор и операторы) |

В группе добавьте имя бота: `/user@yourbot name`. Команды только читают; из чата
изменить в панели ничего нельзя.

## Почта

**Сервисы → Почта.** Те же уведомления, по почте.

| Настройка | |
| --- | --- |
| SMTP-сервер | имя почтового сервера, например `smtp.gmail.com` — без схемы и порта |
| Порт | пусто = 587 для STARTTLS, 465 для TLS, 25 без шифрования |
| Безопасность | **STARTTLS** шифрует обычное соединение (обычно 587); **TLS** шифрует с первого байта (обычно 465); **Нет** отправляет всё, включая логин, без шифрования — только для релея на этом же сервере или в частной сети |
| Сертификат | **Не проверять** — только для своего сервера с самоподписанным сертификатом |
| Имя пользователя, пароль | пустое имя = без входа |
| Отправитель | `Nexora <panel@example.com>`; большинство серверов отправляют только с вашего адреса |

**Gmail** и большинство крупных провайдеров не принимают обычный пароль по SMTP
(`534 Application-specific password required`): включите двухэтапную проверку для
учётной записи и используйте **пароль приложения**.

**Добавление адреса.** *Добавить адрес* отправляет на него шестизначный код; адрес
добавляется, когда код введён обратно. На неподтверждённый адрес ничего не отправляется
— опечатка не отправит имена ваших клиентов постороннему. Код действует десять минут
и пять попыток. Каждая учётная запись может добавить свой адрес из своего меню
(**Моя почта**), и адрес реселлера получает уведомления только о его клиентах.
**Доставки** в строке адреса показывают, что на него было отправлено, как и для
чата.

## Хранилища бэкапов

**Сервисы → Хранилища бэкапов.** Каждая копия, которую создаёт панель — по
расписанию или вручную в **Настройки → Резервная копия**, — в фоне отправляется
ещё и в каждое включённое место.

**Неудачная загрузка никогда не делает копию неудачной.** Архив остаётся на этом
сервере, место показывает ошибку, уходит событие `panel.backup_upload_failed` (и в
Telegram с почтой, если они его слушают), а следующий архив отправляется снова.

**Сначала задайте пароль копий** (Настройки → Резервная копия). Архив содержит
все учётные данные панели; без шифрования они у любого, кто может читать место
хранения. Пока пароля нет, страница предупреждает об этом.

### S3-совместимое хранилище

Cloudflare R2, AWS S3, Backblaze B2, MinIO, иранские объектные хранилища — всё, что
говорит на S3.

| Настройка | |
| --- | --- |
| Адрес | адрес хранилища без бакета: `https://<account>.r2.cloudflarestorage.com`, `https://s3.<region>.amazonaws.com`, `https://s3.<region>.backblazeb2.com`, ваш MinIO |
| Регион | пусто = `us-east-1`, который принимают R2 и MinIO; AWS нужен регион самого бакета |
| Бакет | должен уже существовать |
| Ключ доступа, секретный ключ | ключ с правом записи, просмотра списка и удаления в этом бакете |
| Папка | папка внутри бакета; пусто = его корень |
| Хранить | сколько архивов держать там; пусто = срок хранения со страницы резервного копирования, `0` = все |

### SFTP

Любой сервер, к которому вы подключаетесь по SSH.

| Настройка | |
| --- | --- |
| Хост, порт | без схемы; пустой порт = 22 |
| Имя пользователя | |
| Пароль, закрытый ключ | одно или оба; ключ в формате PEM или OpenSSH, без пароля |
| Ключ хоста | заполняется при первом подключении и проверяется при каждом следующем — очищайте, только если тот сервер переустановлен |
| Каталог | создаётся, если его нет; пусто = домашний каталог пользователя |
| Хранить | как для S3 |

Архив записывается под временным именем и переименовывается, когда загружен целиком,
поэтому недогруженный файл никогда не выглядит как копия.

### Telegram

Архив файлом в чате, через бота, сохранённого в сервисе Telegram, и через его прокси.
**ID чата** — чат, привязанный к учётной записи главного администратора, число, которое
страница Telegram показывает под ним. Bot API принимает файлы до **50 МБ**; больший
архив отклоняется с этой причиной, а не отправляется, чтобы упасть. Из чата ничего не
удаляется.

**Хранение.** Из места хранения удаляются только файлы с именами, как у архивов панели,
так что в том же бакете или каталоге может лежать и другое.

## Единый вход

**Сервисы → Единый вход.** Кнопка **Войти через …** на странице входа для каждого
добавленного провайдера. Два правила действуют для любого провайдера:

- **Учётные записи из этого не создаются.** Каждая учётная запись привязывает свою
  личность сама: входит по паролю, открывает **Единый вход** в своём меню и нажимает
  *Привязать через …*. Человек с учётной записью у провайдера, но без привязки здесь,
  получает отказ.
- **Двухфакторная аутентификация остаётся.** Учётную запись с кодом после провайдера
  спросят код, как и после пароля.

**Redirect URI.** Страница показывает один адрес, который нужно зарегистрировать у
каждого провайдера, — он заканчивается на `/api/login/oidc/callback`. Это адрес, по
которому открыта страница, поэтому перед копированием откройте панель по адресу, которым
пользуются ваши операторы.

**Добавление провайдера.** *Добавить провайдера*, выберите его вверху — форма спросит
ровно то, что нужно этому провайдеру, а над полями написано, где у него создать клиента:

| Провайдер | Что заполнить |
| --- | --- |
| Google | Client ID, Client secret |
| Microsoft | Tenant (пусто = `common`, любая учётная запись Microsoft), Client ID, Client secret |
| GitHub | Client ID, Client secret |
| GitLab | Адрес (пусто = gitlab.com), Client ID, Client secret |
| Keycloak | Адрес, Realm, Client ID, Client secret |
| Authentik | Адрес, slug приложения, Client ID, Client secret |
| Okta | Домен, Authorization server (пусто = `default`), Client ID, Client secret |
| Auth0 | Домен, Client ID, Client secret |
| OpenID Connect (другой) | Issuer, Client ID, Client secret, Scopes — PocketID, Authelia, Zitadel, Kanidm, Dex и подобные |
| OAuth 2.0 (другой) | адреса authorization, token и user, Client ID, Client secret и какие поля ответа о пользователе — его id и имя |

*Проверить* убеждается, что провайдер отвечает. *Название кнопки* меняет её текст;
*На странице входа* убирает кнопку, не удаляя провайдера. Удаление провайдера удаляет и
привязанные через него личности.

**Потеряли доступ?** `nexora-panel admin reset-password` также удаляет привязки единого
входа учётной записи и выключает её двухфакторную аутентификацию, так что команда
восстановления остаётся единственным путём назад — см.
[потеряли доступ?](install.md#потеряли-доступ)

## Дополнения

Дополнение — отдельная программа со своим контейнером или сервисом, интерфейсом
и базой данных, которая работает с панелью по сети. Панель никогда его не
запускает и не показывает его страницы внутри себя; она хранит то, что нужно для
работы с ним: адрес, ссылку на его интерфейс, путь проверки здоровья и две вещи,
которые ему могут быть выданы, — **API-токен** и **вебхук**. Список — в
*Сервисы → Дополнения*.

**Подписанное дополнение** (выпущенное Nexora) регистрируется по коду привязки:

1. Запустите дополнение. Оно показывает одноразовый **код привязки** в журнале
   или на своей странице.
2. *Зарегистрировать подписанное*, введите адрес дополнения, *Прочитать*. Панель
   прочитает его манифест, проверит подпись Nexora и покажет, что оно
   запрашивает: каждое право токена с причиной и каждое событие для вебхука.
3. Введите код привязки и нажмите *Одобрить и зарегистрировать*. Панель создаёт
   ровно этот токен и вебхук и передаёт их дополнению; оно принимает их только со
   своим кодом. Неверный код ничего после себя не оставляет.

**Собственное дополнение** — бот или скрипт, который вы запускаете сами, —
добавляется вручную: *Добавить своё дополнение*, затем имя, адрес, ссылка входа и
путь здоровья, и включите **API-токен** (выберите права) и/или **вебхук** (путь
под адресом и события). Сохранение показывает токен и секрет подписи вебхука
**один раз**; внесите их в настройки своей программы. Токен и вебхук потом
редактируются в той же форме.

**Адрес.** Обычный `http://` принимается только для дополнения на этом сервере,
в частной сети или в сети Docker. В остальных случаях нужен `https://` с
действительным сертификатом, потому что туда отправляется токен дополнения.

Токен и вебхук дополнения видны также в *Доступ → API-токены* и *Сервисы →
Вебхуки* с меткой *Дополнение: имя*, и там их нельзя удалить или изменить.
**Удалить** на странице дополнений сначала уведомляет само дополнение
(`panel.addon_removed`), затем удаляет его токен и вебхук. То, что дополнение
хранило рядом с вашими пользователями, остаётся, поэтому повторная регистрация
это найдёт. События `panel.addon_registered` и `panel.addon_removed` можно
отправлять в Telegram, на почту или в любой вебхук.
